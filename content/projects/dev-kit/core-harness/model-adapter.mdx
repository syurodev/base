# Model adapter

Trạng thái: foundation decision v0.10. **Thiết kế đã chốt** cho H-07 (adapter và converter), H-08 (usage và cost) và H-09 (account, auth, chọn model) trong [bản đồ thiết kế](/dev-kit/core-harness/design-map). Tên option của SDK được xác minh trong spike ([mục 10](#10-spike-và-evidence)).

Tham khảo: pi-ai (stream chuẩn hóa, auth, chuyển model, system message và tool giữa hội thoại), deepseek-harness (`llm`, `llm-retry`, `token-meter`), module `accounts` và cơ chế failover account của Agent Hub, tài liệu [Sign in with ChatGPT cho ứng dụng mã nguồn mở](https://developers.openai.com/siwc/token-sharing-open-source) của OpenAI.

## 1. Quyết định

| ID | Quyết định |

| M-04 | **Failover giữa các account cùng provider và cùng model**; không tự chuyển sang model hoặc provider khác |

## 2. Contract

Contract nằm phía kernel, không phụ thuộc provider. Model adapter chỉ chuyển đổi giữa contract và wire format.

**Request**

| Field | Nội dung |
| --- | --- |
| `model` | ID trong catalog (§5) |
| `transcript` | Message user, assistant, tool result; **system message giữa hội thoại** cho patch của context engine; thay đổi tool (`toolsAdded`, `toolsRemoved`) theo `ToolBindingRevised` |
| `tools` | Khai báo theo binding revision hiện hành |
| `reasoning` | Mức chuẩn hóa `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`; adapter map theo model, mức không hỗ trợ thì hạ về mức gần nhất và ghi lại |
| `maxOutput` | Giới hạn output cho attempt |
| `cacheMarks` | Vị trí điểm cache do context engine đánh dấu (sau L3 và ở cuối) |
| `sessionAffinity` | ID ổn định theo session để provider giữ cache và định tuyến |
| `account` | Account đã chọn cho attempt (§7) |

**Stream event**

| Event | Ý nghĩa | Map sang kernel |
| --- | --- | --- |
| `start` | Provider bắt đầu trả dữ liệu | `ModelStreamStarted` |
| `text_*`, `thinking_*`, `toolcall_*` (`start`, `delta`, `end`) | Khối nội dung; xen kẽ được, gắn theo `contentIndex` | Delta là attempt view (ephemeral); phần cần giữ lưu thành partial ref |
| `done` | Kết thúc có `stopReason` và usage | `ModelResponseRecorded` |
| `error` | Kết thúc lỗi, có lớp lỗi (§3), partial content và usage nếu biết | `ModelRequestFailed` hoặc `ModelRequestInterrupted` |

Luật:

- Stream **không throw sau khi đã `start`**; mọi kết thúc đều là `done` hoặc `error`. Lỗi trước `start` chỉ có `error`.
- Args của tool call chỉ hợp lệ ở `toolcall_end`; vẫn phải qua validate của tool system.
- `stopReason`: `stop`, `tool_use`, `length`, `refusal`, `error`, `aborted`. `length` kèm tool call dở dang thì tool call đó nhận result lỗi có kiểu, không chạy.
- Telemetry không chứa prompt, text, thinking hay args (INV-09).

## 3. Phân loại lỗi và retry

| Lớp | Ví dụ | Xử lý |
| --- | --- | --- |
| `rate_limit` | 429 | Retry được; dùng `Retry-After` nếu có |
| `overloaded`, `server` | 5xx, 529 | Retry được |
| `timeout`, `transport` | Hết thời gian hoặc đứt kết nối **trước** `start` | Retry được |
| `empty_response` | `done` không có nội dung | Retry được |
| `context_overflow` | Provider báo prompt quá dài | Đường compaction rồi retry một lần (context engine §6.2) |
| `auth`, `permission` | Key sai, thu hồi, thiếu quyền | Fatal; thử failover account (§7) nếu account khác hợp lệ |
| `quota` | Hết quota hoặc billing | Fatal cho account đó; failover account |
| `invalid_request`, `model_not_found` | Request sai, model không tồn tại | Fatal, không retry |
| `refusal`, `content_filter` | Model hoặc provider từ chối | Result có kiểu, không retry |
| Đứt **sau** `start` mà không có kết thúc | Stream bị cắt giữa chừng | `Interrupted` theo state machine §4; không đoán đã xong hay chưa |

**Retry mặc định** (cấu hình được theo provider): tối đa 5 lần cho các lớp retry được; backoff mũ từ 500 ms tới 10 s, jitter 10%; `Retry-After` thay backoff nếu không vượt trần 60 s. `Retry-After` dài hơn trần thì kernel đặt timer bền và run vào `Waiting(retry_timer)`. Mỗi retry là một attempt mới, được ghi trước khi chờ, và tính vào retry budget (kể cả attempt bị gián đoạn do host crash).

Circuit breaker theo provider và account để giai đoạn B.

## 4. Converter

- **Đổi model giữa các run**: bỏ thinking của model khác (chữ ký và reasoning mã hóa chỉ hợp lệ với model đã sinh ra nó). **Cùng model** thì gửi lại thinking kèm chữ ký khi tiếp tục sau tool call; thinking được lưu trong canonical response (protected), không hiển thị cho model khác.
- **System message giữa hội thoại**: model có cờ hỗ trợ thì gửi đúng vị trí để giữ cache; model không hỗ trợ thì gộp prompt hiện hành và tool hiện hành lên đầu (mất cache một lần).
- **Đổi tool giữa hội thoại**: model có cờ giữ cache khi đổi tool thì dùng cơ chế native của provider; không có thì gửi danh sách tool hiện hành ở đầu (phương án mặc định của tool system §4).
- **Tool cũ trong history** (tool đã bị gỡ hoặc đổi version): giữ khai báo tối thiểu nếu provider yêu cầu, hoặc render tool call thành text; không bao giờ gửi request sai protocol.
- **Provider-hosted tools**: adapter từ chối mọi cấu hình bật chúng trước khi gửi, kể cả mặc định ngầm của SDK.
- Thứ tự khối trong một response được giữ nguyên; khối loại lạ từ provider làm attempt thất bại có kiểu, không bị bỏ qua lặng lẽ.

## 5. Catalog và khả năng của model

Catalog được đóng gói theo version DevKit, user override được, và có discovery cho endpoint local ở giai đoạn sau.

| Nhóm | Field |
| --- | --- |
| Định danh | `id`, `provider`, `apiFamily`, tên hiển thị, trạng thái (active, deprecated) |
| Giới hạn | `contextWindow`, `maxOutput` |
| Giá | input, output, đọc cache, ghi cache (theo thời gian sống của cache nếu provider tách) |
| Khả năng | mức reasoning hỗ trợ, nhận ảnh, system message giữa hội thoại, đổi tool giữ cache, thời gian sống prompt cache, tool calling |
| Mặc định | mức reasoning, `maxOutput` mặc định |

Context engine đọc `contextWindow` và `maxOutput` để tính ngưỡng compaction; budget đọc giá để tính cost. Run ghim catalog version cùng model (D-07).

## 6. Usage và cost (H-08)

- Usage chuẩn hóa: `input`, `output`, `cacheRead`, `cacheWrite`, `reasoning` (phần của output). Cost = usage × giá trong catalog đã ghim.
- Ghi bằng `BudgetObserved` theo attempt; attempt bị gián đoạn giữ reservation, **không bao giờ ghi 0** (state machine §9). `ModelUsageReconciled` bổ sung sau nếu provider có số liệu.
- Mốc token cho context engine là input token của response trước khi request y hệt; còn lại thì ước lượng (context engine §5).
- UI theo run, session và workspace: token theo loại, tỷ lệ cache hit, cost. Account không tính theo token thì hiện token và giới hạn thay vì tiền.
- `usagemetrics` hiện đo text do host phục vụ, không phải token của provider; usage của model ở trên là nguồn riêng, không trộn.

## 7. Account, auth và chọn model (H-09)

**Credential**

| Loại | Dùng cho | Lưu |
| --- | --- | --- |
| API key | Anthropic (Claude Console) ở giai đoạn A | `internal/accounts` + vault |
| OAuth | Chỉ provider mà điều khoản cho phép ứng dụng bên thứ ba dùng; kiểm tra điều khoản trước khi thêm từng provider. Giai đoạn A: **Sign in with ChatGPT** (§11) | `internal/accounts` + vault; refresh tuần tự hóa, không refresh trùng |
| Cloud provider | Bedrock, Vertex (sau) | Theo cơ chế credential của cloud đó |

- Adapter nhận credential **tường minh** từ accounts; không đọc biến môi trường như `ANTHROPIC_API_KEY`. Key của provider bị redact khỏi output của tool và shell (env snapshot có thể chứa nó).
- Credential không vào journal, log hay audit; journal chỉ ghi account ID.

**Failover**

- Dùng lại logic `PickAccount` của Agent Hub: ngưỡng, chiến lược (`order`, `best`, `consumeFirst`), giữ account 5 phút, biên quay lại. Dữ liệu đầu vào lấy từ **rate-limit header** của API thay cho cửa sổ giới hạn của subscription.
- Chọn account **trước mỗi attempt**; account được ghi trong `ModelDispatchStarted`. Đổi account không đổi model và không đổi binding.
- Mọi account cùng model đều bị giới hạn thì run vào `Waiting(retry_timer)` tới thời điểm reset sớm nhất, hoặc kết thúc nếu vượt budget.
- **Không tự chuyển model hay provider.** User đổi model giữa các run; context engine tính lại ngưỡng, cache bắt đầu nguội.

**Chọn model**

- Mặc định theo workspace, đổi được khi tạo session và giữa các run. Mức reasoning theo session, đổi được giữa các run.
- Model mà catalog đánh dấu deprecated vẫn chạy được nhưng UI cảnh báo.

## 8. SDK

Ưu tiên `anthropic-sdk-go` với các điều kiện sau. Điều kiện nào SDK không đáp ứng thì phần đó viết HTTP/SSE riêng.

| Điều kiện | Lý do |
| --- | --- |
| Tắt retry của SDK (số lần retry = 0) | Kernel sở hữu retry và attempt |
| Đọc được response và header gốc | `Retry-After`, rate-limit header, request ID |
| Truyền key tường minh, không đọc env | Credential chỉ đến từ accounts |
| Tắt telemetry ghi nội dung của SDK | INV-09 |
| Nhận event stream gốc, không chỉ message đã gộp | Map đúng `start`, delta, `done`, `error` |
| Bật được beta header theo request | Cờ khả năng của model (cache, đổi tool giữa hội thoại) |
| Timeout và HTTP client tự cấu hình | Hủy theo context của attempt |

SDK nằm trong package adapter, không lọt vào package stdlib-only (`harness`, `harnessconfig`, `agentwork`); vị trí chốt ở G-01.

## 11. OpenAI và Sign in with ChatGPT

Nguồn: tài liệu [Sign in with ChatGPT cho ứng dụng mã nguồn mở](https://developers.openai.com/siwc/token-sharing-open-source) của OpenAI, gồm các trang Accounts and sessions, Models and inference, Errors and recovery, Preview limitations và [UI/UX guidelines](https://developers.openai.com/siwc/ui-ux-guidelines). Chương trình đang ở dạng preview; mọi chi tiết dưới đây được kiểm tra lại trong spike và khi OpenAI cập nhật.

### 11.1 Hai đường dùng OpenAI trong DevKit

| | Vendor runtime (đã có) | Native runtime (mới) |
| --- | --- | --- |
| Vòng lặp | `codex app-server` (Codex sở hữu) | Kernel của DevKit |
| Gọi model | Codex tự gọi | Model adapter gọi `POST /v1/responses` |
| Auth | Login của Codex trong Codex home | Credential của DevKit trong `internal/accounts` + vault (M-10) |

Vì OpenAI cho phép dùng gói ChatGPT trong ứng dụng mã nguồn mở, giai đoạn C ([activation](/dev-kit/core-harness/activation)) **có thể áp dụng cho Codex** khi native runtime với OpenAI đạt tiêu chí giai đoạn B.

### 11.2 Đăng ký và token

- **Agent host ID**: mỗi bản cài DevKit tạo một `urn:uuid:` (UUIDv4) ổn định, lưu trong data dir trước lần đăng nhập đầu. Không chứa email hay thông tin nhận dạng; không phải credential.
- **Đăng ký lần đầu**: `client_id=dynamic_agent_client`, `ext_agent_host_id`, `agent_name_hint=DevKit`, PKCE, `state`, `nonce`. Callback trả `client_id` được cấp; lưu theo account và dùng lại cho mọi lần đăng nhập sau của account đó.
- **Scope**: `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`. Sau khi đăng nhập phải **kiểm tra scope được cấp có `chatgpt.tokens.use.direct`**. Thiếu thì giữ đăng nhập nhưng tắt plan usage, đề nghị user bật lại hoặc dùng API key.
- **Validate ID token**; chỉ gửi ID token tới endpoint authorize của OpenAI.
- **Lưu token**: access, refresh và ID token nằm trong `internal/accounts` + vault; không vào log, journal, audit, URL hay báo cáo lỗi; URL authorize có ID token bị redact khỏi chẩn đoán.
- **Refresh**: gần hết hạn thì refresh bằng `client_id` đã lưu (không dùng `dynamic_agent_client`), bỏ `scope` để giữ grant cũ; lưu refresh token mới; refresh tuần tự hóa theo account.
- **Nhiều account**: mỗi đăng ký tách riêng (thông tin, `client_id`, token), có nhãn ổn định; không trộn `client_id` của đăng ký này với token của đăng ký khác.
- **Đăng xuất**: dừng request, thu hồi refresh token ở endpoint revocation (kèm `client_id`). Không xác nhận được thì xóa token local và nhắc user ngắt kết nối app trong ChatGPT Settings. Giữ ánh xạ account → `client_id` và host ID cho lần đăng nhập sau.

### 11.3 Ràng buộc request với gói ChatGPT

| Ràng buộc | Hệ quả cho converter |
| --- | --- |
| `store: false`, `stream: true` bắt buộc; thành công chỉ khi có `response.completed` | Khớp contract (§2); `response.incomplete` và stream bị cắt xử lý riêng |
| Không có `previous_response_id` qua HTTP | Gửi lại toàn bộ history trong `input` mỗi request; đây vốn là cách context engine lắp prompt |
| Item vai `system` bị từ chối | L1 đi vào `instructions`; patch của context engine (§2.1) đi dưới dạng **developer message** |
| Không nhận `temperature`, `top_p`, `max_output_tokens`, `metadata`, `user`, `truncation`, `prompt` và vài field khác | Cờ khả năng tính theo cặp **(model, loại auth)**; `maxOutput` của contract bị bỏ qua khi dùng gói ChatGPT |
| Tool: chỉ function và custom (theo namespace hoặc `additional_tools`) | Khớp M-07; `ToolBindingRevised` dùng `additional_tools` khi model hỗ trợ; không dùng `tool_search` của Responses |
| Không có image generation, file search, Code Interpreter, computer use, hosted MCP/connectors | Đã cấm sẵn (M-07) |
| Model hợp lệ lấy từ `GET /v1/models` với cùng token, chỉ giữ `visibility: "list"` | Danh sách model theo **account**, làm mới khi đổi account; catalog của DevKit chỉ bổ sung giá và khả năng |

Với API key, các ràng buộc riêng của gói ChatGPT không áp dụng; converter vẫn dùng Responses API.

### 11.4 Lỗi của gói ChatGPT

| Mã | Lớp (§3) | Xử lý |
| --- | --- | --- |
| 429 `subscription_sharing_usage_limit_exceeded` | `quota` | Dừng request bằng gói này; **không tự retry, không tự chuyển billing** (M-09); không đoán thời điểm reset; UI hiện "Manage usage" |
| 403 `subscription_sharing_user_not_eligible` | `permission` | Giải thích; không lặp request hay OAuth |
| 403 `chatpass_v2_scope_not_authorized`, `chatpass_v2_invalid_authorization_context` | `permission` | Kiểm tra cấu hình client và grant |
| 403 `subscription_sharing_route_not_supported` | `invalid_request` | Lỗi tích hợp |
| 400 `subscription_sharing_unsupported_capability` | `invalid_request` | Đọc `error.param`; với tool thì kiểm tra lại binding; không gửi lại cùng body |
| 401 `subscription_sharing_invalid_user` | `auth` | Giữ request ID; chỉ yêu cầu đăng nhập lại khi đã xác nhận bị thu hồi hoặc refresh lỗi cuối |
| 503 `subscription_sharing_usage_unavailable`, `subscription_sharing_user_unavailable` | `server` | Retry có giới hạn, giữ credential |
| Refresh: `invalid_grant`, `refresh_token_*`, `token_expired` | `auth` | Xóa token hỏng, đăng nhập lại với `client_id` đã lưu |
| Refresh: `invalid_client` | `auth` | Lỗi cấu hình |

Lỗi hạn mức có thể đến dưới dạng `response.failed` **sau khi stream đã bắt đầu**. Khi đó attempt thất bại với lớp `quota`, không phải `Interrupted`, vì có kết thúc rõ ràng. Gói Plus có giới hạn 5 giờ dùng chung cho mọi app dùng gói đó.

### 11.5 Failover với gói ChatGPT

M-09 thắng D-25: account dùng gói ChatGPT **không tham gia failover tự động** sang account khác hay sang API key. Hết hạn mức thì run vào trạng thái chờ user với hai lựa chọn: đợi (theo trang Manage usage của ChatGPT) hoặc chọn rõ một account hay API key khác cho các attempt tiếp theo. Failover tự động vẫn áp dụng giữa các **API key** cùng model.

### 11.6 UI bắt buộc theo hướng dẫn của OpenAI

- Nút bắt đầu đăng nhập ghi **"Continue with ChatGPT"**, đúng định dạng nút được duyệt.
- **Lần đầu** bật plan usage: một thông báo xác nhận, đóng được, nói rằng request AI đủ điều kiện sẽ dùng gói ChatGPT và có thể quản lý trong ChatGPT Settings. Không hiện lại ở các lần sau.
- Khi request đang dùng gói ChatGPT: chỉ báo **"Using ChatGPT plan"** gần ô nhập hoặc chỗ chọn model, kèm link **"Manage usage"**.
- Hết hạn mức: modal hoặc thông báo gọn với hành động chính "Manage usage", vẫn hiện danh tính ChatGPT.
- DevKit không bán credit hay gói riêng, nên không có phần so sánh gói; vẫn ghi rõ gói ChatGPT là tách biệt với mọi chi phí khác (ví dụ API key của user).

| --- | --- |
| SDK | `openai-go` đáp ứng bảng §8 (tắt retry, header gốc, key tường minh, event stream gốc) |
| Reasoning | Giữ reasoning qua nhiều lượt khi `store: false` (encrypted reasoning) có được phép với gói ChatGPT không |
| Cache | Cơ chế giữ cache (ví dụ `prompt_cache_key`) có được nhận với gói ChatGPT không; tỷ lệ cache hit |
| Đổi tool | `additional_tools` khi thêm group giữa session; cách xử lý khi gỡ tool |
| Model | `/v1/models` theo account; khớp với catalog giá |

## 9. Test

- **Faux provider**: provider giả có kịch bản (text, thinking, tool call, lỗi từng lớp, đứt giữa stream) cho headless test và conformance.
- **Golden file**: stream thật của Anthropic được ghi lại (đã redact) để kiểm tra converter hai chiều.
- **Fault injection**: 429 có và không có `Retry-After`, 529, đứt trước và sau `start`, `context_overflow`, key bị thu hồi giữa session, mọi account bị giới hạn.
