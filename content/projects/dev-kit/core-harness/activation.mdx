# Phát hành giai đoạn A và failure UX (G-07)

Trạng thái: **v0.23 đề xuất, ngày 2026-11-25, chờ chủ dự án duyệt** ([D-34](/dev-kit/core-harness/decisions-and-validation)): mọi việc trước đây ghi giai đoạn B đổi thành giai đoạn C; giai đoạn B mới là vòng làm việc hằng ngày trong app (§7.1). **v0.22 đề xuất, ngày 2026-11-23, chờ chủ dự án duyệt** (Fugue FUG-39: A-E02 trỏ tới bảng phân giai đoạn các nhóm VC). v0.21 đề xuất. v0.13 (2026-11-03) chốt giai đoạn A là native runtime với gói ChatGPT. v0.14 đổi hướng theo quyết định của chủ dự án ngày 2026-11-07: giai đoạn A dùng **CLI chính chủ của vendor** chạy bằng gói sub của user ([vendor runtime](/dev-kit/core-harness/vendor-runtime)), có lead giao việc cho worker ([orchestration](/dev-kit/core-harness/orchestration)) và **desktop app viết bằng Gio** ([desktop app](/dev-kit/core-harness/desktop-app)). Native runtime giữ thiết kế đã chốt và sang giai đoạn C qua OpenRouter (M-12). Sửa 2026-11-08: CLI/TUI `fugue` sang giai đoạn C, client duy nhất của giai đoạn A là app Gio (A-06). Sửa 2026-11-23 (v0.15, chủ dự án chốt, Fugue FUG-34): A-E03 là bộ probe gộp gồm invariant lõi theo code chạy ở giai đoạn A và sáu probe bảo mật; bản native của probe lõi sang C cùng native runtime. Sửa 2026-11-23 (v0.16, đề xuất, chờ chủ dự án duyệt, Fugue FUG-37): A-E01 và A-E02 viết lại theo giai đoạn A (evidence của vendor runtime, transcript, desktop app, orchestration, storage-security và điểm kill A-E06), phần chỉ của native sang C; ghi lại VR-12 và VR-E12 ở [mục 7](#7-hoãn-sang-b). Sửa 2026-11-23 (v0.17, đề xuất, chờ chủ dự án duyệt, Fugue FUG-37): A-E04 sang C cùng native runtime (kernel chưa có caller production ở giai đoạn A); dòng G-02 và G-03 của A-E01 khớp theo; A-07 và hai hàng failure UX về ChatGPT viết lại cho CLI vendor, bản native sang C. Sửa 2026-11-23 (v0.18, chủ dự án chốt, Fugue FUG-46): A-E07 (smoke sandbox ba preset) sang C cùng native runtime và tool, vì sandbox jail theo phiên thuộc giai đoạn C (Fugue FUG-26). A-E08 viết lại theo giai đoạn A (Fugue FUG-44): `Waiting(recovery_admission)` là trạng thái của native runtime nên sang C. Bảng failure UX ở §3 phân loại theo code: hàng chỉ có ở native runtime đánh dấu (C), hàng có đường giai đoạn A nhưng khác trạng thái đánh dấu (tách) kèm trạng thái tương đương của giai đoạn A (Fugue FUG-46). Sửa 2026-11-23 (v0.19, chủ dự án chốt, Fugue FUG-51 và FUG-43): `fugue serve` thoát exit 9 khi store có schema mới hơn bản build hiểu, tách khỏi exit 8 của data directory đang bị giữ (hai hàng failure UX ở §3 ghi exit code theo [CLI §5.2](/dev-kit/core-harness/cli#52-exit-code)); A-E06 viết lại điểm kill "commit unknown" theo giai đoạn A, bản run-commit của native sang C. Sửa 2026-11-23 (v0.20, chủ dự án quyết định, Fugue FUG-55): hai hàng failure UX "Chờ quota" và "Chờ worker" ở §3 không còn phiên vendor `Waiting`; phiên do user mở bị từ chối có hướng dẫn, task đội vẫn xếp hàng; chờ ở cấp phiên sau giai đoạn A. Sửa 2026-11-23 (v0.21, đề xuất, chờ chủ dự án duyệt, Fugue FUG-62): A-E02 bỏ S-E11 khỏi danh sách giai đoạn A cho khớp [storage-security §10](/dev-kit/core-harness/storage-security), nơi S-E11 thuộc cổng C. G-07 chỉ đóng khi evidence ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a) đạt.

## 2. Phạm vi giai đoạn A

| Mảng | Trong giai đoạn A |
| --- | --- |
| Process | Một host `fugue serve` giữ data directory ([host API §3](/dev-kit/core-harness/host-api#3-cách-chạy-process)); app tự khởi động host nếu chưa có (DA-07) |
| Client | Desktop app Gio (H-33), client duy nhất. Mọi hành động failure UX ở [mục 3](#3-failure-ux-bắt-buộc) có trên app |
| Vendor | Claude Code, Codex, Antigravity CLI theo [vendor runtime §5](/dev-kit/core-harness/vendor-runtime#5-surface-của-từng-vendor); giữ mặc định của vendor, tuỳ chọn opt-in theo hồ sơ; duyệt quyền qua policy của [interaction](/dev-kit/core-harness/interaction) |
| Orchestration | Tự quyết làm một mình hay đề xuất đội cho user duyệt, đội nhiều tầng, task, scheduler, cổng quota, nhiều account (opt-in), Fugue giữ git, cổng kết quả, merge queue ([orchestration](/dev-kit/core-harness/orchestration)) |
| Transcript | Mô hình item chuẩn hoá ([transcript](/dev-kit/core-harness/transcript)) |
| Lưu trữ | Execution history chỉ local (S-04). Vault phải mở để chạy hoặc resume (S-01, S-02); nội dung transcript là payload được bảo vệ |

Không có trong giai đoạn A: native runtime và tool của native (H-16 đến H-20, H-25, H-28; interaction H-24 và an toàn nội dung H-26, H-27 vẫn dùng cho vendor), provider gọi qua API, peer message, đội sâu hơn 2 tầng, agent trên máy khác, truy cập từ xa, import dữ liệu DevKit, provider-hosted tools (M-07).

## 3. Failure UX bắt buộc

Mỗi tình huống dưới đây MUST hiện trong app, dựng từ read model, nói rõ chuyện gì đã xảy ra và hành động nào có thể làm. Không dùng thông báo lỗi chung chung. Cách hiển thị ở [desktop app §6](/dev-kit/core-harness/desktop-app#6-failure-ux).

| Tình huống | Hiển thị | Hành động |
| --- | --- | --- |
| Mất kết nối với host | "Mất kết nối với lõi Fugue", kèm đường dẫn data directory | App nối lại; không được thì khởi động `fugue serve` theo host API §3 |
| Vault khóa sau process start (tách) | Giai đoạn A: phiên vendor `Waiting(vault_locked)` kèm số phiên đang chờ. Run native `Waiting(vault_locked)` ở C | Mở vault; sau đó vẫn cần resume |
| Chờ resume sau restart (C) | `Waiting(recovery_admission)`, trạng thái của native runtime. Giai đoạn A dùng hàng "Phiên vendor `detached`" bên dưới | `ResumeRun`, hoặc đóng run |
| Tác động không rõ (C) | `Interrupted(effect_unknown)` của native runtime; giai đoạn A là lượt vendor `unknown` và task `unknown` (hai hàng bên dưới): tool, attempt, thời điểm dispatch | Đối soát nếu tool hỗ trợ `Reconcile`; `AcceptUnknown(close)` với preview đúng tham số khi vault mở; `CloseRunWithoutPayload` khi không xem được |
| Mất hoặc hỏng payload (C) | `Interrupted(payload_unavailable)` của native runtime; giai đoạn A chưa có đường nào sinh trạng thái này cho transcript vendor | `CloseRunWithoutPayload`; run sau bắt buộc fresh context |
| Chọn context cho run mới (C) | Lựa chọn fresh hoặc continue, khóa continue khi `fresh_required` | `SelectRunContext` |
| Worker treo, không có stop proof (tách) | Giai đoạn A: đóng phiên vendor mà stop proof là `unknown` thì phiên `closed` với stop proof `unknown`, không coi là đã dừng. Run native với "Cần khởi động lại host Fugue để đóng run này" ở C; nói rõ restart không chứng minh tác động bên ngoài đã dừng | Restart host |
| Hết quota của vendor giữa lượt | Lượt `failed(quota)`, account `paused` ([vendor runtime §11](/dev-kit/core-harness/vendor-runtime#11-failure-và-recovery)); vendor, account, thời điểm reset vendor báo (nếu có); không đoán thời điểm làm mới | Chờ, chuyển account (nếu bật), hoặc để orchestration giao lại cho account hay vendor khác |
| Chưa đăng nhập hoặc token của vendor hết hạn | Lượt `failed(auth)`, account `needs_login`, tên vendor và account ([vendor runtime §11](/dev-kit/core-harness/vendor-runtime#11-failure-và-recovery), [orchestration](/dev-kit/core-harness/orchestration)); run chờ, không mất lịch sử | Đăng nhập lại bằng luồng login của chính CLI (VR-03) |
| Chạm budget của run (tách) | Giai đoạn A: budget của đội (`teams.TeamBudget`, host `teamBudgets`). Run native chờ `budget(kind)` ở C, kèm loại (token, thời gian, tool calls, step) và mức đã dùng ([budget và quota §4](/dev-kit/core-harness/budget#4-budget-theo-run)) | Gia hạn trong cùng run, hoặc kết thúc |
| Chờ quota (tách) | Giai đoạn A: phiên vendor không chờ; phiên không còn quota thất bại `failed(quota)` với account `paused` và giờ reset ([vendor runtime §11](/dev-kit/core-harness/vendor-runtime#11-failure-và-recovery)), còn task đội `queued` bởi cổng quota. Chờ quota ở cấp phiên (sau giai đoạn A). Run native `Waiting(quota_refresh)` ở C: giờ reset nếu biết, hoặc chờ resume account | Phiên: chờ giờ reset, chuyển account hoặc resume account. Task đội: không cần làm gì, hoặc resume account |
| Chờ worker (tách) | Giai đoạn A: phiên do user mở vượt `max_sessions` bị từ chối `vendor.capacity`, message nêu đang chạy/giới hạn và cách xử lý; task đội `queued` theo scheduler tiers. Chờ capacity ở cấp phiên (sau giai đoạn A). Run native `Waiting(worker_capacity)` ở C | Phiên: đóng một phiên hoặc tăng `max_sessions`. Task đội: không cần làm gì |
| Data directory đang bị process khác giữ | Execution store unavailable, kèm đường dẫn data directory; `fugue serve` thoát exit 8 ([CLI §5.2](/dev-kit/core-harness/cli#52-exit-code)) | Đóng process kia |
| Schema hoặc protocol không hỗ trợ (A) | Giai đoạn A: protocol bị từ chối ở `Hello` với `unsupported_version` (client nhận exit 8 theo [CLI §2.3](/dev-kit/core-harness/cli#23-version)); schema mới hơn bị từ chối `failed_precondition` trước mọi thao tác ghi (A-E08), và `fugue serve` thoát exit 9 ([CLI §5.2](/dev-kit/core-harness/cli#52-exit-code)). Stream chỉ đọc hoặc unavailable, hiện version của app và của host | Nâng cấp Fugue (host hoặc app) |
| CLI của vendor thiếu, chưa đăng nhập hoặc version ngoài dải đã kiểm | Tên CLI, version, dải đã kiểm ([vendor runtime §11](/dev-kit/core-harness/vendor-runtime#11-failure-và-recovery)) | Cài hoặc nâng cấp CLI; đăng nhập bằng lệnh của CLI |
| Phiên vendor `detached` hoặc lượt `unknown` sau khi host khởi động lại | Phiên, lượt, thời điểm | Resume bằng lệnh của vendor, hoặc đóng; không tự chạy lại |
| Task `unknown` hoặc cổng kết quả từ chối | Trạng thái worktree, diff, lý do ([orchestration §10](/dev-kit/core-harness/orchestration#10-cổng-kết-quả)) | Tiếp tục, trả về worker, giữ diff, huỷ |
| Account vendor `paused` | Vendor, account, thời điểm reset vendor báo | Chờ, chuyển account (nếu bật), hoặc giao task cho vendor khác |

Mọi preview chỉ hiện metadata cho phép theo INV-09; nội dung payload chỉ hiện khi vault mở, trong client tin cậy. Host headless thì interaction là `unavailable`, fail closed; không có client nào đang nối thì request chờ ([interaction](/dev-kit/core-harness/interaction) I-07).

## 4. Nâng cấp và hạ phiên bản (G-06)

Thay cho mục rollback của v0.12. G-06 với Fugue nghĩa là: **lịch sử đọc được sau nâng cấp, hạ phiên bản không bao giờ ghi, lệch protocol được xử lý ở bước bắt tay**.

- Không có cờ bật hay tắt. Ngừng dùng là không chạy Fugue nữa; data directory giữ nguyên.
- Migration chỉ đi tới. Fugue **không tự sao lưu** `fugue.db` trước migration: bản sao lưu giữ lại wrapped key, nên session bị xóa sau đó vẫn phục hồi được từ bản sao, đúng giới hạn đã ghi ở [storage-security §7](/dev-kit/core-harness/storage-security#7-xóa-export-và-backup).
- Binary cũ gặp schema hoặc protocol mới hơn: unavailable hoặc chỉ đọc theo [event storage §9](/dev-kit/core-harness/event-storage-recovery#9-payload-security-compatibility-và-client-delivery); không append, không đoán.
- App và host lệch version: `Hello` ([host API §8](/dev-kit/core-harness/host-api#8-version)) quyết định. Không hỗ trợ thì từ chối kết nối và hiện cả hai version.
- Runtime và provider ghim theo run như state machine đã chốt; nâng cấp không đổi chúng giữa run.

## 5. Evidence để phát hành giai đoạn A

Mọi mục kèm revision cụ thể; spike dùng dữ liệu giả không tính. Cách kiểm chứng, tầng chạy và bản ghi live theo [bộ kiểm chứng](/dev-kit/core-harness/verification); quy trình phát hành ở [bộ kiểm chứng §7](/dev-kit/core-harness/verification#7-phát-hành).

- **A-E01** (v0.16, đề xuất) G-01 đến G-06 đóng theo định nghĩa ở [open decisions](/dev-kit/core-harness/decisions-and-validation#open-decisions-trước-implementation), với evidence của giai đoạn A như sau. Phần chỉ có nghĩa với native runtime sang giai đoạn C cùng native runtime (A-01):
  - **G-01** (package và owner): arch test đạt trên code giai đoạn A: [HA-E06](/dev-kit/core-harness/host-api#10-evidence) (domain không import code proto) và [DA-E06](/dev-kit/core-harness/desktop-app#10-evidence) (module lõi không import module UI, app không có đường ghi ngoài Host API).
  - **G-02** (transition protocol): review kernel native ([state machine §10](/dev-kit/core-harness/state-machine#10-review-g-02-h-05)), các scenario VC viết cho kernel và invariant checker SM-01 đến SM-12 (A-E04) sang C cùng native runtime. Giai đoạn A: G-02 dựa trên A-E03 (probe invariant lõi), A-E06 (điểm kill), [VR-E06](/dev-kit/core-harness/vendor-runtime#15-evidence) (host crash giữa lượt) và [OR-E09](/dev-kit/core-harness/orchestration#15-evidence) (host crash với task đang chạy).
  - **G-03** (storage và bảo mật payload): các mục S-E của giai đoạn A ở [storage-security §10](/dev-kit/core-harness/storage-security#10-evidence-để-đóng-g-03): S-E03, S-E07, S-E08, và phần giai đoạn A của S-E01, S-E04, S-E05, S-E09, S-E13 (bảng `vendor_*` và `exec_host`); S-E02, S-E06, S-E10, S-E11, S-E12 và phần native của các mục còn lại sang C. Cộng [TR-E04](/dev-kit/core-harness/transcript#9-evidence) và TR-E08 (payload của item được mã hoá, secret bị che) và VR-E11 (vault khoá giữa lượt).
  - **G-04** (model và tool): phần ChatGPT adapter, provider-hosted tool và canonical tool path của bộ tool native sang C (A-E09 và nhóm `M-E` ở [verification §2](/dev-kit/core-harness/verification#2-id)). Giai đoạn A: đường vào model là CLI chính chủ bằng login của user (VR-03) với VR-E01 đến VR-E03 (conformance), VR-E04 (duyệt quyền với account thật) và VR-E09 (env không chứa secret); đường tool của Fugue là tool MCP phục vụ phiên vendor qua `fugue mcp-bridge` với VR-E13, OR-E10 và OR-E11 (xem I-E phần giai đoạn A ở [interaction §11](/dev-kit/core-harness/interaction#11-evidence)).
  - **G-05** (interaction): các mục I-E được đánh dấu giai đoạn A ở [interaction §11](/dev-kit/core-harness/interaction#11-evidence), cùng VR-E04, VR-E13 và [DA-E05](/dev-kit/core-harness/desktop-app#10-evidence) (hàng failure UX có test e2e); các mục I-E của kernel native sang C.
  - **G-06** (compatibility): A-E08 (upgrade và downgrade drill), [HA-E05](/dev-kit/core-harness/host-api#10-evidence) (lệch version bị từ chối ở `Hello`) và [mục 4](#4-nâng-cấp-và-hạ-phiên-bản-g-06).
- **A-E02** (v0.16, đề xuất) [Tiêu chí kiểm chứng](/dev-kit/core-harness/decisions-and-validation#tiêu-chí-kiểm-chứng) đạt cho phần chạy trên code giai đoạn A, bằng test headless với deterministic clock và fault injection ([verification V-07](/dev-kit/core-harness/verification#1-quyết-định)): `fugue serve` thật với vendor là CLI giả phát lại fixture ([verification §3](/dev-kit/core-harness/verification#3-harness)). Evidence của giai đoạn A nằm ở các họ: vendor runtime (VR-E01 đến VR-E03, VR-E05, VR-E06, VR-E08, VR-E11), transcript (TR-E01 đến TR-E03), desktop app (DA-E04, DA-E05, DA-E08), orchestration (OR-E02, OR-E07 đến OR-E09), storage-security (S-E07, S-E08) và điểm kill ở A-E06. Các nhóm VC viết cho kernel native (**VC-03** vòng đời model, **VC-12** provider tool, **VC-21** transcript native, **VC-27** partial tool JSON của model) sang C cùng native runtime và provider. Phân giai đoạn của mọi nhóm VC (A, C hoặc tách, kèm evidence giai đoạn A) ở [decisions-and-validation](/dev-kit/core-harness/decisions-and-validation#phân-giai-đoạn-các-nhóm-vc) (v0.22, Fugue FUG-39).
- **A-E03** (v0.15, chủ dự án chốt 2026-11-23) Bộ mutation probe gộp; mỗi probe làm đúng các test khai báo fail ([bộ kiểm chứng §3](/dev-kit/core-harness/verification#3-harness)). Invariant lõi của thiết kế được ánh xạ sang code chạy thật ở giai đoạn A (vendor runtime, app Gio, team):
  - CAS: bỏ CAS ở sequence event của session vendor, sequence event của team, revision của tài liệu state app.
  - Current authority: trả lời interaction của incarnation cũ không bị từ chối; delegator hành động ngoài subtree của chính nó.
  - Không dispatch khi replay hoặc khôi phục sau restart: restart host đưa task team đang chạy về `unknown` rồi chạy lại chúng; restart host để lượt vendor đang mở không được đóng thành `unknown`.
  - Không retry `unknown`: task `unknown` rời trạng thái này bằng retry thay vì quyết định recovery tường minh.
  - Cancellation không phải stop proof: đóng session được ghi là đã chứng minh dù không có stop proof; stop chưa chứng minh vẫn nhả owner của peer; kết quả signal một mình được coi là stop proof.
  - Bảo mật (sáu probe đã có): vault fail-open, nâng quyền principal của session, vendor auto-approve lách duyệt, `decide` lách luật cứng, team ghi ngoài write scope, workspace path traversal.
  - Bản native của các probe lõi (admission fence và queue của `execstore`, lease và current authority của `coordinator`, replay và unknown tool attempt của `kernel`) **sang giai đoạn C cùng native runtime**, vì `execstore`, `kernel`, `coordinator` chưa có caller production ở giai đoạn A (cùng hướng với A-01 và v0.14 ở trên). Bỏ so khớp `grantScopeKey` vẫn là yêu cầu của [I-E10](/dev-kit/core-harness/interaction), chưa có probe ở giai đoạn A.
- **A-E04** (C) Invariant checker SM-01 đến SM-12 chạy sau mỗi batch trong build test và build dogfood. Ở build dogfood, vi phạm dừng run đó và ghi chẩn đoán; không có vi phạm nào trong evidence. v0.17: chuyển sang cổng C cùng native runtime, vì kernel chưa có caller production ở giai đoạn A (A-E03).

Bản commit của run native thuộc native runtime nên sang C cùng native runtime. (v0.14: điểm kill của native chuyển sang C.)

Upgrade drill: đang có lượt vendor thì dừng host, cài build mới, khởi động lại; session vendor ở trạng thái `detached`, transcript ghi trước lúc kill đọc được, đúng một lượt tồn tại với kết quả `unknown` và không bị chạy lại. ## 6. A ổn định

Chủ dự án tự dùng giai đoạn A và **duyệt** khi thấy ổn định; quyết định ghi kèm ngày và revision. Trước khi duyệt, các ngưỡng sau MUST đạt; con số chỉ đổi bằng quyết định ghi lại.

| ID | Tiêu chí | Ngưỡng |
| --- | --- | --- |
| **A-S01** (stable) | Recovery drill | ≥ 20 lần kill có chủ đích với CLI vendor thật, phủ các điểm kill ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a); trong đó ≥ 5 lần trên macOS (v0.14: thay "ChatGPT thật") |
| **A-S02** (stable) | An toàn | 0 vi phạm SM-01 đến SM-12; 0 effect bị dispatch hai lần; 0 lần `Interrupted` không giải thích được nguyên nhân |
| **A-S03** (stable) | Độ trễ | Từ lúc gửi prompt trên app đến lúc tin nhắn được ghi vào stdin hoặc socket của CLI vendor: p50 ≤ 100 ms, p95 ≤ 300 ms (v0.14: thay mốc "model request rời host") |

A ổn định không tự mở giai đoạn sau. Giai đoạn B mở theo quyết định của chủ dự án ngày 2026-11-25 ([D-34](/dev-kit/core-harness/decisions-and-validation)), làm song song với việc đưa A tới ổn định.

## 7. Giai đoạn B và C

### 7.1 Giai đoạn B: vòng làm việc hằng ngày trong app

Giai đoạn B làm cho desktop app phục vụ đúng vòng việc hằng ngày của chủ dự án:

- nhận task Jira và đọc ngữ cảnh ở Confluence;
- làm task nhỏ trong một phiên, task lớn bằng đội;
- chạy e2e, review code, tìm trong source;
- ghi checklist;
- theo dõi PR.

Agent đã làm việc với Jira, Confluence và GitHub qua MCP của user trong Claude Code ([VR-04](/dev-kit/core-harness/vendor-runtime#4-quyết-định)); các mảng dưới đây là phía app. Mỗi mảng cần trang thiết kế được duyệt trước khi viết code.

1. [Task hub](/dev-kit/core-harness/task-hub) (H-52): một việc gom các phiên, đội, note, checklist, nhánh, PR và CI.
2. Module contract (H-53).
3. Module Terminal (H-54), để chạy e2e. Cần sửa DA-02 của [desktop app](/dev-kit/core-harness/desktop-app).
4. Module Git và PR (H-55): review nhánh hoặc PR, theo dõi PR, CI và review.
5. Notes và checklist của user (H-56).
6. Tìm trong source cho user (H-57).
7. Sau các mục trên: module API client (H-58) và Database (H-59).
8. Việc còn lại của đội: dừng và chạy lại task, telemetry usage theo task và đội, gán account trong thẻ đề xuất.

### 7.2 Hoãn sang C

Chỉ là danh sách; phạm vi và tiêu chí của C là quyết định riêng.

- Failure UX của tầng native: hết hạn mức gói ChatGPT ([budget và quota §3.1](/dev-kit/core-harness/budget#31-gói-chatgpt)) và đăng nhập ChatGPT hết hiệu lực (refresh lỗi hoặc token bị thu hồi; đăng nhập lại với `client_id` đã lưu).
- Native runtime và tool của Fugue (kernel, H-16 đến H-28), provider qua API: OpenRouter trước (M-12), Sign in with ChatGPT, API key OpenAI, Anthropic (M-01), failover giữa account của tầng native (M-04).
- CLI/TUI `fugue` (H-45), sau một lượt sửa cho vendor runtime.
- ZCode và CLI vendor khác: chỉ thêm khi có surface có cấu trúc chính chủ và qua đủ evidence của trang vendor runtime ([VR-12](/dev-kit/core-harness/vendor-runtime#4-quyết-định); ZCode còn chờ kiểm chứng ở [§5.4](/dev-kit/core-harness/vendor-runtime#5-surface-của-từng-vendor)). GLM qua Claude Code (adapter Claude với endpoint Z.ai, key từ vault) là evidence [VR-E12](/dev-kit/core-harness/vendor-runtime#15-evidence) của cổng C, cần đạt trước khi bật.
- Đọc code bằng LSP và codegraph (H-19), web (H-21), MCP và plugin (H-23), attachment (H-14), tham chiếu session cũ (H-15).
- Observability (H-38), hiệu năng ngoài ngưỡng ở mục 6 (H-40).
- Windows; đóng gói, ký code, auto-update; người dùng ngoài chủ dự án; truy cập từ xa; import dữ liệu DevKit.
