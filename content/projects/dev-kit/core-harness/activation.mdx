# Phát hành giai đoạn A và failure UX (G-07)

Trạng thái: v0.13, viết lại ngày 2026-11-03 để trả lời Q-02 trong roadmap của Fugue. Trang này thay toàn bộ bản v0.12, vốn giả định native runtime chạy cạnh vendor runtime bên trong DevKit. **Fugue là sản phẩm riêng**: không có vendor session, không có cờ opt-in, không rollback về vendor. G-07 chỉ đóng khi evidence ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a) đạt.

## 1. Quyết định của người dùng

| A-02 | Provider duy nhất của giai đoạn A là **OpenAI Responses với Sign in with ChatGPT** ([model adapter §11](/dev-kit/core-harness/model-adapter#11-openai-và-sign-in-with-chatgpt)). Quyết định này đảo M-01 cho Fugue (ghi ở M-11). API key OpenAI, Anthropic và failover giữa account sang B |

## 2. Phạm vi giai đoạn A

| Mảng | Trong giai đoạn A |
| --- | --- |
| Process | Một host `fugue serve` giữ data directory ([host API §3](/dev-kit/core-harness/host-api#3-cách-chạy-process)); CLI tự khởi động host nếu chưa có |
| Client | CLI/TUI `fugue` là client tin cậy duy nhất: tạo và chạy session, trả lời interaction, mở vault, đăng nhập ChatGPT, xem job và snapshot, mọi hành động failure UX ở [mục 3](#3-failure-ux-bắt-buộc). Thiết kế chi tiết ở H-45 |
| Provider | OpenAI Responses, auth bằng gói ChatGPT. Đăng nhập từ CLI theo §11.2 (PKCE, `state`, `nonce`, mở trình duyệt hệ thống). Các chữ bắt buộc của §11.6 hiện dạng text trong CLI: "Continue with ChatGPT", thông báo lần đầu bật plan usage, "Using ChatGPT plan" kèm link "Manage usage". Không failover tự động (M-09) |
| Tool | File: read, grep, glob, edit, write, patch (H-17). Shell và job (H-18, H-25). `ask_user`, plan, todo (H-20). Turn và tool snapshot, restore (H-28) |
| Preset | Chỉ đọc / Workspace / Full access theo [tool system §5.2](/dev-kit/core-harness/tool-system#52-preset-theo-workspace). Với Workspace và Full access, CLI MUST nói rõ network là `host`: sandbox chặn ghi ngoài workspace nhưng **không chặn dữ liệu bị gửi ra ngoài** |
| Lưu trữ | Execution history chỉ local (S-04). Vault phải mở để chạy hoặc resume (S-01, S-02) |

Không có trong giai đoạn A: vendor session, peer message, child session và subagent, tool song song, remote worker, truy cập từ xa, import dữ liệu DevKit, provider-hosted tools (M-07).

## 3. Failure UX bắt buộc

Mỗi tình huống dưới đây MUST hiện trong CLI, dựng từ read model, nói rõ chuyện gì đã xảy ra và hành động nào có thể làm. Không dùng thông báo lỗi chung chung. Tên lệnh chốt ở H-45.

| Tình huống | Hiển thị | Hành động |
| --- | --- | --- |
| Mất kết nối với host | "Mất kết nối với lõi Fugue", kèm đường dẫn data directory | CLI nối lại; không được thì khởi động `fugue serve` theo host API §3 |
| Vault khóa sau process start | `Waiting(vault_locked)` kèm số run đang chờ | Mở vault; sau đó vẫn cần resume |
| Chờ resume sau restart | `Waiting(recovery_admission)` | `ResumeRun`, hoặc đóng run |
| Tác động không rõ | `Interrupted(effect_unknown)`: tool, attempt, thời điểm dispatch | Đối soát nếu tool hỗ trợ `Reconcile`; `AcceptUnknown(close)` với preview đúng tham số khi vault mở; `CloseRunWithoutPayload` khi không xem được |
| Mất hoặc hỏng payload | `Interrupted(payload_unavailable)` | `CloseRunWithoutPayload`; run sau bắt buộc fresh context |
| Chọn context cho run mới | Lựa chọn fresh hoặc continue, khóa continue khi `fresh_required` | `SelectRunContext` |
| Worker treo, không có stop proof | "Cần khởi động lại host Fugue để đóng run này"; nói rõ restart không chứng minh tác động bên ngoài đã dừng | Restart host |
| Hết hạn mức gói ChatGPT | Run chờ user, danh tính ChatGPT, link "Manage usage"; không đoán thời điểm hạn mức được làm mới ([model adapter §11.4–11.5](/dev-kit/core-harness/model-adapter#114-lỗi-của-gói-chatgpt)) | Đợi, hoặc chọn rõ một account ChatGPT khác cho các attempt tiếp theo |
| Đăng nhập ChatGPT hết hiệu lực | Refresh lỗi lần cuối hoặc token bị thu hồi; run chờ, không thất bại | Đăng nhập lại với `client_id` đã lưu |
| Hết budget | Outcome `budget_exceeded` kèm loại budget (token, thời gian, tool calls, storage) | Tạo run mới với budget mới |
| Chờ worker | `Waiting(worker_capacity)` | Không cần làm gì |
| Data directory đang bị process khác giữ | Execution store unavailable, kèm đường dẫn data directory | Đóng process kia |
| Schema hoặc protocol không hỗ trợ | Stream chỉ đọc hoặc unavailable, hiện version của CLI và của host | Nâng cấp Fugue (host hoặc CLI) |

Mọi preview chỉ hiện metadata cho phép theo INV-09; nội dung payload chỉ hiện khi vault mở, trong client tin cậy. Host không có answerer tin cậy (headless, nil responder) thì interaction là `unavailable`, fail closed.

## 4. Nâng cấp và hạ phiên bản (G-06)

Thay cho mục rollback của v0.12. G-06 với Fugue nghĩa là: **lịch sử đọc được sau nâng cấp, hạ phiên bản không bao giờ ghi, lệch protocol được xử lý ở bước bắt tay**.

- Không có cờ bật hay tắt. Ngừng dùng là không chạy Fugue nữa; data directory giữ nguyên.
- Migration chỉ đi tới. Fugue **không tự sao lưu** `fugue.db` trước migration: bản sao lưu giữ lại wrapped key, nên session bị xóa sau đó vẫn phục hồi được từ bản sao, đúng giới hạn đã ghi ở [storage-security §7](/dev-kit/core-harness/storage-security#7-xóa-export-và-backup).
- Binary cũ gặp schema hoặc protocol mới hơn: unavailable hoặc chỉ đọc theo [event storage §9](/dev-kit/core-harness/event-storage-recovery#9-payload-security-compatibility-và-client-delivery); không append, không đoán.
- CLI và host lệch version: `Hello` ([host API §8](/dev-kit/core-harness/host-api#8-version)) quyết định. Không hỗ trợ thì từ chối kết nối và hiện cả hai version.
- Runtime và provider ghim theo run như state machine đã chốt; nâng cấp không đổi chúng giữa run.

## 5. Evidence để phát hành giai đoạn A

Mọi mục kèm revision cụ thể; spike dùng dữ liệu giả không tính.

- G-01 đến G-06 đã đóng; [evidence G-03](/dev-kit/core-harness/storage-security#10-evidence-để-đóng-g-03) đạt. G-04 tính trên adapter ChatGPT và bộ tool ở [mục 2](#2-phạm-vi-giai-đoạn-a).
- Toàn bộ nhóm trong [tiêu chí kiểm chứng](/dev-kit/core-harness/decisions-and-validation#tiêu-chí-kiểm-chứng) đạt bằng test headless, với deterministic clock và fault injection.
- Mutation probes ở cùng trang đều làm test fail: bỏ CAS, bỏ current-authority check, dispatch khi replay, retry unknown, coi cancellation là stop proof.
- Invariant checker SM-01 đến SM-12 chạy sau mỗi batch trong build test và build dogfood. Ở build dogfood, vi phạm dừng run đó và ghi chẩn đoán; không có vi phạm nào trong evidence.
- Mỗi hàng ở [mục 3](#3-failure-ux-bắt-buộc) có test e2e: CLI chạy với `fugue serve` thật, model là faux provider; kể cả host headless fail closed.
- Fault injection kill host ở các điểm: model stream, tool dispatch, chờ approval, commit unknown, job shell đang chạy. Chạy trên Linux và macOS trong CI.
- Smoke sandbox với ba preset trên Linux và macOS.
- Upgrade drill: đang có run thì dừng host, cài build mới, resume; run đi qua `Waiting(recovery_admission)` và tiếp tục đúng guards. Downgrade drill: build cũ mở data directory mới thì không append.
- [Spike OpenAI §11.7](/dev-kit/core-harness/model-adapter#117-spike-riêng-cho-openai) và luồng đăng nhập §11.2 từ CLI đã chạy với account ChatGPT thật.

## 6. A ổn định

Chủ dự án tự dùng giai đoạn A và **duyệt** khi thấy ổn định; quyết định ghi kèm ngày và revision. Trước khi duyệt, các ngưỡng sau MUST đạt; con số chỉ đổi bằng quyết định ghi lại.

| Tiêu chí | Ngưỡng |
| --- | --- |
| Recovery drill | ≥ 20 lần kill có chủ đích với ChatGPT thật, phủ các điểm kill ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a); trong đó ≥ 5 lần trên macOS |
| An toàn | 0 vi phạm SM-01 đến SM-12; 0 effect bị dispatch hai lần; 0 lần `Interrupted` không giải thích được nguyên nhân |
| Độ trễ | Từ lúc gửi prompt đến lúc model request rời host: p50 ≤ 2 s, p95 ≤ 5 s |

A ổn định không tự mở giai đoạn B.

## 7. Hoãn sang B

Chỉ là danh sách; phạm vi và tiêu chí của B là quyết định riêng sau khi A ổn định.

- Electron desktop và UI session (H-44, H-33).
- API key OpenAI, Anthropic (M-01), failover giữa account (M-04).
- Đọc code bằng LSP và codegraph (H-19), web (H-21), MCP và plugin (H-23), attachment (H-14), tham chiếu session cũ (H-15).
- Observability (H-38), hiệu năng ngoài ngưỡng ở mục 6 (H-40).
- Windows; đóng gói, ký code, auto-update; người dùng ngoài chủ dự án; truy cập từ xa; import dữ liệu DevKit.
