# Phát hành giai đoạn A và failure UX (G-07)

Trạng thái: **v0.14 đề xuất, ngày 2026-11-07, chờ chủ dự án duyệt**. v0.13 (2026-11-03) chốt giai đoạn A là native runtime với gói ChatGPT. v0.14 đổi hướng theo quyết định của chủ dự án ngày 2026-11-07: giai đoạn A dùng **CLI chính chủ của vendor** chạy bằng gói sub của user ([vendor runtime](/dev-kit/core-harness/vendor-runtime)), có lead giao việc cho worker ([orchestration](/dev-kit/core-harness/orchestration)) và **desktop app viết bằng Gio** ([desktop app](/dev-kit/core-harness/desktop-app)). Native runtime giữ thiết kế đã chốt và sang giai đoạn B qua OpenRouter (M-12). Sửa 2026-11-08: CLI/TUI `fugue` sang giai đoạn B, client duy nhất của giai đoạn A là app Gio (A-06). G-07 chỉ đóng khi evidence ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a) đạt.

## 2. Phạm vi giai đoạn A

| Mảng | Trong giai đoạn A |
| --- | --- |
| Process | Một host `fugue serve` giữ data directory ([host API §3](/dev-kit/core-harness/host-api#3-cách-chạy-process)); app tự khởi động host nếu chưa có (DA-07) |
| Client | Desktop app Gio (H-33), client duy nhất. Mọi hành động failure UX ở [mục 3](#3-failure-ux-bắt-buộc) có trên app |
| Vendor | Claude Code, Codex, Antigravity CLI theo [vendor runtime §5](/dev-kit/core-harness/vendor-runtime#5-surface-của-từng-vendor); giữ mặc định của vendor, tuỳ chọn opt-in theo hồ sơ; duyệt quyền qua policy của [interaction](/dev-kit/core-harness/interaction) |
| Orchestration | Tự quyết làm một mình hay đề xuất đội cho user duyệt, đội nhiều tầng, task, scheduler, cổng quota, nhiều account (opt-in), Fugue giữ git, cổng kết quả, merge queue ([orchestration](/dev-kit/core-harness/orchestration)) |
| Transcript | Mô hình item chuẩn hoá ([transcript](/dev-kit/core-harness/transcript)) |
| Lưu trữ | Execution history chỉ local (S-04). Vault phải mở để chạy hoặc resume (S-01, S-02); nội dung transcript là payload được bảo vệ |

Không có trong giai đoạn A: native runtime và tool của native (H-16 đến H-20, H-25, H-28; interaction H-24 và an toàn nội dung H-26, H-27 vẫn dùng cho vendor), provider gọi qua API, peer message, đội sâu hơn 2 tầng, agent trên máy khác, truy cập từ xa, import dữ liệu DevKit, provider-hosted tools (M-07).

## 3. Failure UX bắt buộc

Mỗi tình huống dưới đây MUST hiện trong app, dựng từ read model, nói rõ chuyện gì đã xảy ra và hành động nào có thể làm. Không dùng thông báo lỗi chung chung. Cách hiển thị ở [desktop app §6](/dev-kit/core-harness/desktop-app#6-failure-ux).

| Tình huống | Hiển thị | Hành động |
| --- | --- | --- |
| Mất kết nối với host | "Mất kết nối với lõi Fugue", kèm đường dẫn data directory | App nối lại; không được thì khởi động `fugue serve` theo host API §3 |
| Vault khóa sau process start | `Waiting(vault_locked)` kèm số run đang chờ | Mở vault; sau đó vẫn cần resume |
| Chờ resume sau restart | `Waiting(recovery_admission)` | `ResumeRun`, hoặc đóng run |
| Tác động không rõ | `Interrupted(effect_unknown)`: tool, attempt, thời điểm dispatch | Đối soát nếu tool hỗ trợ `Reconcile`; `AcceptUnknown(close)` với preview đúng tham số khi vault mở; `CloseRunWithoutPayload` khi không xem được |
| Mất hoặc hỏng payload | `Interrupted(payload_unavailable)` | `CloseRunWithoutPayload`; run sau bắt buộc fresh context |
| Chọn context cho run mới | Lựa chọn fresh hoặc continue, khóa continue khi `fresh_required` | `SelectRunContext` |
| Worker treo, không có stop proof | "Cần khởi động lại host Fugue để đóng run này"; nói rõ restart không chứng minh tác động bên ngoài đã dừng | Restart host |
| Hết hạn mức gói ChatGPT | Account bị tạm dừng, danh tính ChatGPT, link "Manage usage"; không đoán thời điểm hạn mức được làm mới ([budget và quota §3.1](/dev-kit/core-harness/budget#31-gói-chatgpt)) | Chuyển sang tài khoản ChatGPT khác (tự động nếu có), resume account sau khi xem trang Usage, hoặc chọn rõ một API key |
| Đăng nhập ChatGPT hết hiệu lực | Refresh lỗi lần cuối hoặc token bị thu hồi; run chờ, không thất bại | Đăng nhập lại với `client_id` đã lưu |
| Chạm budget của run | Run chờ `budget(kind)` kèm loại (token, thời gian, tool calls, step) và mức đã dùng ([budget và quota §4](/dev-kit/core-harness/budget#4-budget-theo-run)) | Gia hạn trong cùng run, hoặc kết thúc |
| Chờ quota | `Waiting(quota_refresh)`: giờ reset nếu biết, hoặc chờ resume account | Không cần làm gì, hoặc resume account |
| Chờ worker | `Waiting(worker_capacity)` | Không cần làm gì |
| Data directory đang bị process khác giữ | Execution store unavailable, kèm đường dẫn data directory | Đóng process kia |
| Schema hoặc protocol không hỗ trợ | Stream chỉ đọc hoặc unavailable, hiện version của app và của host | Nâng cấp Fugue (host hoặc app) |
| CLI của vendor thiếu, chưa đăng nhập hoặc version ngoài dải đã kiểm | Tên CLI, version, dải đã kiểm ([vendor runtime §11](/dev-kit/core-harness/vendor-runtime#11-failure-và-recovery)) | Cài hoặc nâng cấp CLI; đăng nhập bằng lệnh của CLI |
| Phiên vendor `detached` hoặc lượt `unknown` sau khi host khởi động lại | Phiên, lượt, thời điểm | Resume bằng lệnh của vendor, hoặc đóng; không tự chạy lại |
| Task `unknown` hoặc cổng kết quả từ chối | Trạng thái worktree, diff, lý do ([orchestration §10](/dev-kit/core-harness/orchestration#10-cổng-kết-quả)) | Tiếp tục, trả về worker, giữ diff, huỷ |
| Account vendor `paused` | Vendor, account, thời điểm reset vendor báo | Chờ, chuyển account (nếu bật), hoặc giao task cho vendor khác |

Mọi preview chỉ hiện metadata cho phép theo INV-09; nội dung payload chỉ hiện khi vault mở, trong client tin cậy. Host headless thì interaction là `unavailable`, fail closed; không có client nào đang nối thì request chờ ([interaction](/dev-kit/core-harness/interaction) I-07).

## 4. Nâng cấp và hạ phiên bản (G-06)

Thay cho mục rollback của v0.12. G-06 với Fugue nghĩa là: **lịch sử đọc được sau nâng cấp, hạ phiên bản không bao giờ ghi, lệch protocol được xử lý ở bước bắt tay**.

- Không có cờ bật hay tắt. Ngừng dùng là không chạy Fugue nữa; data directory giữ nguyên.
- Migration chỉ đi tới. Fugue **không tự sao lưu** `fugue.db` trước migration: bản sao lưu giữ lại wrapped key, nên session bị xóa sau đó vẫn phục hồi được từ bản sao, đúng giới hạn đã ghi ở [storage-security §7](/dev-kit/core-harness/storage-security#7-xóa-export-và-backup).
- Binary cũ gặp schema hoặc protocol mới hơn: unavailable hoặc chỉ đọc theo [event storage §9](/dev-kit/core-harness/event-storage-recovery#9-payload-security-compatibility-và-client-delivery); không append, không đoán.
- App và host lệch version: `Hello` ([host API §8](/dev-kit/core-harness/host-api#8-version)) quyết định. Không hỗ trợ thì từ chối kết nối và hiện cả hai version.
- Runtime và provider ghim theo run như state machine đã chốt; nâng cấp không đổi chúng giữa run.

## 5. Evidence để phát hành giai đoạn A

Mọi mục kèm revision cụ thể; spike dùng dữ liệu giả không tính. Cách kiểm chứng, tầng chạy và bản ghi live theo [bộ kiểm chứng](/dev-kit/core-harness/verification); quy trình phát hành ở [bộ kiểm chứng §7](/dev-kit/core-harness/verification#7-phát-hành).

- **A-E01** G-01 đến G-06 đã đóng; [evidence G-03](/dev-kit/core-harness/storage-security#10-evidence-để-đóng-g-03) đạt. G-04 tính trên adapter ChatGPT và bộ tool ở [mục 2](#2-phạm-vi-giai-đoạn-a).
- **A-E02** Toàn bộ nhóm trong [tiêu chí kiểm chứng](/dev-kit/core-harness/decisions-and-validation#tiêu-chí-kiểm-chứng) đạt bằng test headless, với deterministic clock và fault injection.
- **A-E03** Mutation probes ở cùng trang đều làm test fail: bỏ CAS, bỏ current-authority check, dispatch khi replay, retry unknown, coi cancellation là stop proof.
- **A-E04** Invariant checker SM-01 đến SM-12 chạy sau mỗi batch trong build test và build dogfood. Ở build dogfood, vi phạm dừng run đó và ghi chẩn đoán; không có vi phạm nào trong evidence.
- **A-E05** Mỗi hàng ở [mục 3](#3-failure-ux-bắt-buộc) có test e2e: app (hoặc client thử dùng `pkg/client`) chạy với `fugue serve` thật, vendor là CLI giả phát lại fixture; kể cả host headless fail closed. (v0.14: model faux đổi thành vendor giả.)
- **A-E06** Fault injection kill host ở các điểm: lượt vendor đang stream, chờ duyệt, commit unknown, task đang chạy, merge queue. Chạy trên Linux và macOS trong CI. (v0.14: điểm kill của native chuyển sang B.)
- **A-E07** Smoke sandbox với ba preset trên Linux và macOS.
- **A-E08** Upgrade drill: đang có run thì dừng host, cài build mới, resume; run đi qua `Waiting(recovery_admission)` và tiếp tục đúng guards. Downgrade drill: build cũ mở data directory mới thì không append.
- **A-E09** (B) [Spike OpenAI §11.7](/dev-kit/core-harness/model-adapter#117-spike-riêng-cho-openai) và luồng đăng nhập §11.2 với account ChatGPT thật. v0.14: chuyển sang cổng B cùng tầng native.
- **A-E10** Evidence cổng `release` của [vendor runtime](/dev-kit/core-harness/vendor-runtime#15-evidence), [transcript](/dev-kit/core-harness/transcript#9-evidence), [orchestration](/dev-kit/core-harness/orchestration#15-evidence) và [desktop app](/dev-kit/core-harness/desktop-app#10-evidence) đạt.

## 6. A ổn định

Chủ dự án tự dùng giai đoạn A và **duyệt** khi thấy ổn định; quyết định ghi kèm ngày và revision. Trước khi duyệt, các ngưỡng sau MUST đạt; con số chỉ đổi bằng quyết định ghi lại.

| ID | Tiêu chí | Ngưỡng |
| --- | --- | --- |
| **A-S01** (stable) | Recovery drill | ≥ 20 lần kill có chủ đích với CLI vendor thật, phủ các điểm kill ở [mục 5](#5-evidence-để-phát-hành-giai-đoạn-a); trong đó ≥ 5 lần trên macOS (v0.14: thay "ChatGPT thật") |
| **A-S02** (stable) | An toàn | 0 vi phạm SM-01 đến SM-12; 0 effect bị dispatch hai lần; 0 lần `Interrupted` không giải thích được nguyên nhân |
| **A-S03** (stable) | Độ trễ | Từ lúc gửi prompt trên app đến lúc tin nhắn được ghi vào stdin hoặc socket của CLI vendor: p50 ≤ 100 ms, p95 ≤ 300 ms (v0.14: thay mốc "model request rời host") |

A ổn định không tự mở giai đoạn B.

## 7. Hoãn sang B

Chỉ là danh sách; phạm vi và tiêu chí của B là quyết định riêng sau khi A ổn định.

- Native runtime và tool của Fugue (kernel, H-16 đến H-28), provider qua API: OpenRouter trước (M-12), Sign in with ChatGPT, API key OpenAI, Anthropic (M-01), failover giữa account của tầng native (M-04).
- CLI/TUI `fugue` (H-45), sau một lượt sửa cho vendor runtime.
- ZCode và CLI vendor khác ([vendor runtime](/dev-kit/core-harness/vendor-runtime) VR-12); GLM qua Claude Code (VR-E12).
- Đọc code bằng LSP và codegraph (H-19), web (H-21), MCP và plugin (H-23), attachment (H-14), tham chiếu session cũ (H-15).
- Observability (H-38), hiệu năng ngoài ngưỡng ở mục 6 (H-40).
- Windows; đóng gói, ký code, auto-update; người dùng ngoài chủ dự án; truy cập từ xa; import dữ liệu DevKit.

## 8. Phụ thuộc

Giai đoạn A cần mọi mảng có giai đoạn A trong [bản đồ thiết kế](/dev-kit/core-harness/design-map) ở trạng thái Đã chốt. Từ v0.14: H-47, H-48, H-49, H-33 (mới), cộng H-03, H-24, H-26, H-27, H-34, H-36, H-39 (phần test), H-42, H-45 và H-06. Các mảng chỉ phục vụ native (H-01, H-05, H-07 đến H-13, H-16 đến H-20, H-25, H-28, H-29, H-31, H-46) chuyển giai đoạn B; thiết kế giữ nguyên.
