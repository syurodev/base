# Transcript

Trạng thái: **đề xuất v0.1, ngày 2026-11-07, chờ chủ dự án duyệt**. Mảng H-48 trong [bản đồ thiết kế](/dev-kit/core-harness/design-map). Nguồn event: [vendor runtime](/dev-kit/core-harness/vendor-runtime) (giai đoạn A) và native run (giai đoạn B). Client đọc: [desktop app](/dev-kit/core-harness/desktop-app) và [CLI](/dev-kit/core-harness/cli).

## 1. Phạm vi

Transcript là **read model** mà mọi UI đọc để hiện một phiên: tin nhắn, suy nghĩ, tool call, thay đổi file, yêu cầu duyệt, task được giao, usage. Mọi vendor và tầng native đều được chuẩn hoá về cùng một tập item, nên UI không biết gì về wire format của từng vendor.

Ngoài phạm vi: tìm kiếm toàn văn (B), export (B), rewind và fork (H-15).

## 2. Quyết định

| ID | Quyết định |
| --- | --- |
| TR-01 | **Một mô hình item** cho phiên vendor và native run. UI chỉ đọc item; không bao giờ đọc payload gốc của vendor |
| TR-02 | Item có ID ổn định, được **ghi một lần rồi cập nhật theo ID** (đổi trạng thái, chốt nội dung). Mọi cập nhật là event bền có sequence |
| TR-03 | Nội dung đang stream đi qua topic **delta tạm** ([host API §6](/dev-kit/core-harness/host-api#6-event-stream)); nội dung cuối cùng ghi bền khi item được chốt. Mất delta thì client đọc lại item |
| TR-04 | Nội dung item (text, args, output, diff, suy nghĩ) là **payload được bảo vệ** dưới khóa của session; metadata theo INV-09 |
| TR-05 | Event gốc của vendor được giữ làm payload được bảo vệ, tham chiếu từ item, chỉ dùng để audit và chẩn đoán |
| TR-06 | Event không nhận ra thành item `notice` loại `unsupported_event`, không bao giờ bị bỏ |

| TR-08 | Mọi nội dung trong transcript là **dữ liệu không tin cậy** ([an toàn nội dung](/dev-kit/core-harness/content-safety)); redact secret khi hiển thị theo CS |

## 3. Loại item

| Kind | Field chính (metadata) | Nội dung (payload) |
| --- | --- | --- |
| `user_message` | origin (`user`, `lead`, `fugue`) | Text, file đính kèm |
| `assistant_message` | model | Text markdown |
| `reasoning` | trạng thái (`plain`, `summary`, `redacted`) | Text suy nghĩ khi vendor cho xem |
| `tool_call` | tool, tiêu đề ngắn, trạng thái (`pending`, `running`, `succeeded`, `failed`, `denied`, `unknown`), exit code, thời lượng | Input, output |
| `file_change` | đường dẫn, loại (`add`, `modify`, `delete`, `rename`), số dòng thêm và bớt | Diff |
| `approval` | loại yêu cầu, quyết định, người quyết định (`user`, `policy`, `lead`), receipt | Nội dung yêu cầu |
| `plan` | số bước, bước đang làm | Danh sách bước |
| `subagent` | tên, trạng thái | Mô tả và kết quả do vendor báo |
| `command` | tên slash command, nguồn (`vendor`, `fugue`) | Tham số |
| `team_proposal` | proposal ID, số agent, quyết định (`pending`, `approved`, `approved_edited`, `solo`, `rejected`) | Kế hoạch đội: vai trò, model, task, phụ thuộc ([orchestration §5.3](/dev-kit/core-harness/orchestration#53-đề-xuất-và-duyệt)) |
| `task_link` | task ID, agent, trạng thái ([orchestration](/dev-kit/core-harness/orchestration)) | Tóm tắt kết quả |
| `usage` | token vào, ra, cache; chi phí nếu vendor báo | — |
| `quota` | account, cửa sổ, mức đã dùng, thời điểm reset | — |
| `notice` | mức (`info`, `warning`, `error`), mã | Text |

Mỗi item có: `item_id`, `session_id`, `turn_id`, `kind`, `seq` khi tạo, `revision` tăng mỗi lần cập nhật, `created_at`, `updated_at`, và tham chiếu tới event gốc (TR-05).

## 5. Stream và cập nhật

- Adapter phát delta (đoạn text, đoạn output) vào topic tạm `transcript-delta:<session>`; delta được gộp tối đa 30 lần mỗi giây.
- Khi item chốt (khối text kết thúc, tool có kết quả), actor của phiên ghi event bền `TranscriptItemRecorded` hoặc `TranscriptItemUpdated` với nội dung đầy đủ.
- Client giữ nội dung delta của item đang mở; nhận bản bền thì thay bằng bản bền. Mất kết nối thì đọc lại từ sequence ([host API §6](/dev-kit/core-harness/host-api#6-event-stream)).

## 6. Read model trên Host API

| RPC hoặc topic | Nội dung |
| --- | --- |
| `TranscriptPage(session, before_seq?, limit)` | Trang item theo thứ tự, mặc định 200 item, mới nhất trước |
| `TranscriptItem(item_id)` | Một item đầy đủ, gồm payload lớn (output, diff) |
| Topic `transcript:<session>` | Event bền: tạo và cập nhật item |
| Topic `transcript-delta:<session>` | Delta tạm |

Payload chỉ trả về khi vault mở, cho client tin cậy.

## 7. Giới hạn

| Giới hạn | Mặc định | Vượt thì |
| --- | --- | --- |
| Text của một item | 512 KiB | Lưu đủ trong payload; item hiện 64 KiB đầu kèm nút xem đầy đủ |
| Output của tool | 64 KiB hiển thị | Đầu 32 KiB và cuối 32 KiB, phần đầy đủ trong payload |
| Diff | 2.000 dòng hiển thị | Gập theo file; đầy đủ trong payload |
| Item mỗi phiên | Không giới hạn | Phân trang; UI chỉ dựng phần đang thấy |

## 8. Hiển thị

- Markdown theo TR-07; tab đổi thành khoảng trắng trước khi vẽ (spike Gio: tab hiện thành ô vuông).
- `reasoning` gập mặc định; `tool_call` gập mặc định trừ khi thất bại; `file_change` hiện số dòng, mở ra là diff.
- Secret được redact khi hiển thị theo [an toàn nội dung](/dev-kit/core-harness/content-safety); payload gốc không đổi.
