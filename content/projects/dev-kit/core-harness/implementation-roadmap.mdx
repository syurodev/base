# Lộ trình triển khai

Trang này là **bảng việc sống** cho agent triển khai. Nó trả lời: làm gì, theo thứ tự nào, dựa trên trang thiết kế nào, thế nào là xong, và việc đang ở đâu. Thiết kế nằm ở các trang khác của core harness; trang này **không** thay đổi thiết kế.

Lần cập nhật cuối: 2026-11-01, bởi agent điều phối (R0.0–R0.3, R1.7, R3.1–R3.2 và baseline một phần R1.1/R1.2 đã merge; PR #419 closure follow-up merged, CI run 41267814115 xanh; G-02 còn một phần).

**Tên sản phẩm:** DevKit được đổi tên thành **Fugue by SynX**; quy tắc đặt tên đã được chốt trong ADR R0.0. Code hiện có vẫn ghi DevKit cho tới khi R0.4 thực hiện đổi tên; code mới dùng tên đã chốt.

## 1. Luật cho agent triển khai

1. **Đọc trước khi làm**: `AGENTS.md` của repo `syurodev/dev-kit`, [architecture rules](https://github.com/syurodev/dev-kit/blob/main/docs/agent-reference/architecture-rules.md), và đúng các trang thiết kế mà việc đó trỏ tới. Không cần đọc mọi trang.
2. **Chỉ làm việc có thiết kế "Đã chốt"** trong [bản đồ thiết kế](/dev-kit/core-harness/design-map). Việc có trạng thái `Chờ thiết kế` thì không bắt đầu, kể cả khi có vẻ đơn giản.
3. **Không tự sửa thiết kế.** Gặp chỗ thiết kế sai, thiếu hoặc mâu thuẫn với code thật thì đặt việc sang `Cần quyết định`, ghi câu hỏi cụ thể ở cột Ghi chú và ở [§6](#6-cần-quyết-định), rồi chuyển sang việc khác không bị chặn.
4. **Không bypass**: không runner thay thế, không bỏ qua gateway, không nới allowlist của `internal/arch` chỉ để test qua. Mở rộng một luật arch phải kèm lý do trong cùng thay đổi, đúng như architecture rules yêu cầu.
5. **Kiểm tra bắt buộc** trước khi đánh dấu xong, theo AGENTS.md:
   - `go test ./internal/... ./cmd/...`
   - `go test ./internal/arch/`
   - `cd frontend && bun test --isolate` và `cd frontend && bun run build` khi có thay đổi frontend
   - `wails3 generate bindings` khi đổi method của `AppService` (cho tới khi gỡ Wails)
   - Từ khi có proto: `buf lint` và `buf breaking` so với `main`
6. **Evidence là test có tên**, không phải mô tả. "Xong" nghĩa là các test trong cột "Xong khi" đã có và pass trên một commit cụ thể.
7. **Nhánh và PR**: mỗi việc (hoặc một nhóm nhỏ việc liền nhau) một nhánh `feat/harness-<id>` từ `main`, một PR vào `main`. Không xếp PR chồng lên PR chưa merge.

## 2. Cách cập nhật trang này

- Mỗi khi đổi trạng thái một việc, sửa dòng của việc đó: **Trạng thái**, **PR / commit** (link đầy đủ tới `github.com/syurodev/dev-kit`), **Ghi chú** (tên test làm evidence, giới hạn còn lại).
- Thêm một dòng vào [nhật ký](#7-nhật-ký) với ngày, ID việc, thay đổi.
- Cập nhật dòng "Lần cập nhật cuối" ở đầu trang.
- Trang này nằm trong repo `syurodev/base` (`content/projects/dev-kit/core-harness/implementation-roadmap.mdx`). Commit riêng ở repo đó, message dạng `docs(dev-kit): roadmap <ID> <trạng thái>`.
- Không sửa các trang thiết kế khác. Nếu một gate (G-01 … G-07) đạt đủ evidence, ghi vào §5 để người thiết kế đóng gate.

**Trạng thái dùng trong bảng**

| Trạng thái | Nghĩa |
| --- | --- |
| `Chưa bắt đầu` | Thiết kế đã chốt, chưa làm |
| `Đang làm` | Có nhánh và commit |
| `Chờ review` | PR đã mở |
| `Xong` | Đã merge vào `main`, evidence pass |
| `Bị chặn` | Chờ một việc khác; ghi ID việc chặn |
| `Cần quyết định` | Thiết kế cần người thiết kế trả lời (§6) |
| `Chờ thiết kế` | Mảng chưa có thiết kế đã chốt; **không làm** |
