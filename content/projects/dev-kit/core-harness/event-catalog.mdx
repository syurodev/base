# Event catalog và execution traces

Trạng thái: foundation contract v0.12, tên/schema logic để review; chưa là public wire API. Đây là catalog tối thiểu của native execution. Event batch được append bởi coordinator; projection được cập nhật đồng bộ như [storage protocol](/dev-kit/core-harness/event-storage-recovery).

## 1. Quy ước

Command là yêu cầu/observation có thể bị từ chối, dedup hoặc no-op; event là fact đã commit. `TimerFired` là command; event được ghi khi nó hợp lệ là `TimerElapsed`. Không dùng cùng một tên để lẫn hai nghĩa.

Envelope chung có run/sequence, command/causation, authenticated origin và writer/admission/executor fences. Pre-admission accept/cancel/timer/metadata-close dùng queue-owner revision thay admission token; chỉ admitted execution mới bắt buộc active-run token. Các field bên dưới bổ sung envelope; nội dung nhạy cảm dùng protected refs. `origin=model` không phải authority; `origin=worker/timer/recovery` phải do host-bound ingress xác lập.

`RunWaitEntered/Exited`, `PhaseChanged`, `IntentInserted` và `TranscriptAppended` không có trong catalog v1: chúng là projection/derived changes từ facts dưới đây, không là nguồn dữ liệu thứ hai.

## 2. Run và step

| Event | Fields/control facts chính | Guard / thay đổi projection |
| --- | --- | --- |
| `RunAccepted` | Input ref, session/queue item ref, protocol/config binding, initial budgets, `origin`, lớp ưu tiên, peer outbox item ref nếu có; `goal_id` và số vòng khi `origin=goal` ([điều phối input](/dev-kit/core-harness/coordination)) | Run ID mới; tạo `Queued`; chưa đưa queued input vào transcript đang chạy |
| `RunAdmitted` | Admission token, owner incarnation, queue decision reference, context epoch/startRunID và initial context revision nếu là admission đầu | CAS session admission thành công; materialize input trong canonical transcript |
| `RunOwnershipAcquired` | Token mới, previous token, recovery receipt và data-directory lock generation | Chỉ session owner trong process giữ exclusive lock phục hồi cùng active run; cùng batch thêm recovery dependency, đồng bộ vault theo owner revision, không tạo dispatch |
| `RunStopRequested` | Reason, mode terminal/suspend, actor, target, request time | Ghi stop intent; terminal primary reason không bị callback ghi đè |
| `RunBlockAdded` | Blocker ID/kind/reference, resume condition | Thêm dependency có kiểu; lifecycle/wait reasons được suy ra |
| `RunBlockCleared` | Blocker ID, resolving owner evidence | Chỉ đúng dependency/version và current authority; không tự dispatch |
| `RunInterrupted` | Typed cause, affected attempt/payload refs | Ghi interruption cause cần đối soát/can thiệp, khác wait dependency của `RunBlockAdded`; không phát chỉ vì run đang Queued lúc restart |
| `RunRecoveryCleared` | Cause IDs, owner evidence, disposition reconciled/accepted_unknown/closed_unavailable, authorized next action | Clear đúng interruption, không xóa unknown evidence cũ hoặc tự gỡ user/vault blocks |
| `UnknownAccepted` | Exact target attempts/revisions, actor, accepted uncertainty, disposition `close` | Trusted user command v1; đặt terminal control dispositions; exposure vẫn unknown |
| `RunClosureConfirmed` | Metadata-only preview version, run revision, exact attempt/cause IDs, actor, unavailability enum, previous/new contextRevision khi ảnh hưởng admitted history, resulting contextRequirement và cause event ref, terminal attempt/cause dispositions | Chỉ CloseRunWithoutPayload qua trusted user ingress; không cần vault, không phải effect/stop proof; terminal dispositions/StepAborted nếu có/RunFinished cùng batch sau SM-05 |
| `ContextBoundarySelected` | Target queued run, old/new contextRevision/epoch, startRunID, mode fresh/continue, actor, validation evidence và previous deciding-event ref | SelectRunContext qua trusted user ingress; cùng RunAdmitted + update admission row/transcript epoch; fresh_required cấm continue, vault_locked chỉ revalidation |
| `RunFinished` | Outcome, cờ `truncated` nếu có, primary/secondary stop refs, unresolved exposure refs nếu có | Mọi invocation đã có control disposition; cancel timers/dependencies, clear đúng control admission nếu run sở hữu nó; Queued finish không clear admission của run khác |
| `StepStarted` | Step index, context/config refs | Step trước đã đóng; tạo model frontier, chưa gọi model |
| `ToolBindingRevised` | Old/new binding revision, groups thêm/bớt, descriptor versions, cause (session_start, user_selection, propose, revoke, upgrade) | Chỉ ở ranh giới step: không có step mở hoặc attempt đang chạy; step kế tiếp dùng binding mới ([tool system §4](/dev-kit/core-harness/tool-system#4-registry-và-nạp-tool)) |
| `InstructionsLoaded` | Lớp rule (R1/R2/R3), đường dẫn nguồn, payload refs của snapshot, budget và phần bị cắt | Snapshot rule và instruction file dùng để lắp context; nạp lại khi file đổi ([context engine §3](/dev-kit/core-harness/context-engine#3-tầng-rule)) |
| `ContextInjected` | Tag, nguồn (patch rule/W/preset, runtime context, rule theo path, job đã xong), payload ref | Message có nhãn gắn vào cuối view; không sửa prefix ([context engine §2.1](/dev-kit/core-harness/context-engine#21-patch-và-runtime-context)) |
| `ToolResultsPruned` | Vị trí các tool result, tham số cắt, token tiết kiệm | Chỉ khi vượt ngưỡng và tiết kiệm đủ; bản gốc giữ nguyên trong payload |
| `ContextCompacted` | Payload bản tóm tắt, vị trí giữ nguyên đầu tiên, token trước/sau, W references, model invocation ref | Chỉ ở ranh giới step, trong cùng epoch; transcript gốc không đổi ([context engine §6.2](/dev-kit/core-harness/context-engine#62-compaction)) |
| `InputSteered` | Input ref, origin, thời điểm | Chờ chèn; mọi steer đang chờ được gộp và chèn ở ranh giới step kế tiếp qua `ContextInjected` ([điều phối input](/dev-kit/core-harness/coordination) §4) |
| `InputInterjected` | Input ref, các steer được gộp, target attempt/invocation, kết quả quiesce | Chỉ user; tool `side_effecting` đang chạy luôn được chờ xong; result tổng hợp, message và model request mới trong cùng batch ([điều phối input](/dev-kit/core-harness/coordination) §5) |
| `StepCompleted` | Response ref, ordered result refs, field `continuation` (lý do chạy tiếp hoặc kết thúc, [continuation](/dev-kit/core-harness/continuation) §2) | Canonical response và tool pairs đủ; next action end/continue có budget/stop checks |
| `BudgetExtended` | Kind ∈ `steps`, `tokens`, `time`, `tool_calls`, lượng gia hạn, actor | Chỉ user; resolve wait dependency `budget(kind)` ([budget và quota](/dev-kit/core-harness/budget) §4), run chạy tiếp trong cùng run, không đếm lại từ đầu ([continuation](/dev-kit/core-harness/continuation) §3) |
| `StepAborted` | Typed reason và dispositions của batch đã xuất hiện | Dùng khi stop/fatal/unknown close trước normal completion; đóng model invocation còn mở bằng disposition tương ứng (unknown close là abandoned_unknown); không giả response/failure đã biết |

Ghim input/config phục vụ provenance, không ghim quyền. Admission guards và execution authorization vẫn đọc owner hiện tại. Host không đọc được schema thì không được ghi `RunInterrupted` vào stream đó để đoán state.

`UnknownAccepted` không tự hoàn tất step/run. Coordinator cùng batch ghi `ToolResultRecorded(outcome=abandoned_unknown)` cần thiết, `StepAborted`, cancellation timers và `RunFinished(abandoned_unknown)` sau khi kiểm tra guards. Sự chấp nhận này chỉ đóng execution control, không chấp thuận chạy lại thao tác ghi.

## 3. Model invocation và attempts

| Event | Fields/control facts chính | Guard / thay đổi projection |
| --- | --- | --- |
| `ModelRequestPlanned` | Invocation ID, purpose (`turn` hoặc `compaction`), first attempt ID, model/context/tool declaration refs, budget estimate | Tạo logical model invocation ở step frontier; no side effect |
| `ModelDispatchStarted` | Attempt ID, executor fence, reservation, selected provider settings ref, account ID và catalog version ([model adapter](/dev-kit/core-harness/model-adapter) §7) | Coordinator sở hữu admission; không blocker/stop; chuyển attempt `Requesting` trước handoff |
| `ModelStreamStarted` | Attempt ID, first chunk observation ref | Bound worker report; chuyển `Streaming`; các deltas sau không cần domain event từng token |
| `ModelResponseRecorded` | Complete response ref, selected attempt, usage status | Valid final protocol record; chuyển `Completed`, chọn response và project canonical assistant message |
| `ModelRequestFailed` | Stage, failure class/code, retry disposition, usage status, partial ref nếu có | Terminal error evidence; không chuyển transport uncertainty thành known failure |
| `ModelRequestInterrupted` | Attempt, uncertainty class, partial ref, usage reservation | Thiếu completion/stop proof; giữ output gắn đúng attempt và chưa đưa vào canonical context |
| `ModelRetryScheduled` | Previous attempt, new attempt ID, policy version, retry number, timer ID | Known retryable failure hoặc attempt đã được abandon theo policy; **một batch** với `ModelAttemptPlanned` và `TimerScheduled(model_retry)`, ghi trước khi chờ; charge retry budget (số lần) tại đây |
| `ModelAttemptPlanned` | New attempt ID, previous attempt, same invocation, budget estimate | Cùng batch với `ModelRetryScheduled`, trước khi chờ; attempt ở `Planned` cho tới khi timer elapsed; admission, budget và blockers được kiểm tại `ModelDispatchStarted`; không sửa attempt cũ |
| `ModelAttemptCancelled` | Pre-dispatch hoặc terminal/quiescence evidence | Không dùng request cancellation làm bằng chứng đã dừng |
| `ModelAttemptAbandoned` | Uncertainty, policy/user receipt, next action retry/close, unknown cost | Có authority/policy hữu hạn; close đi cùng StepAborted để đóng invocation bằng abandoned_unknown; retry giữ invocation mở; không ghi usage zero hoặc response giả |
| `ModelInvocationFailed` | Final failure ref, exhausted/fatal decision | Không còn retry được phép; đóng logical invocation để abort step/finish run |
| `ModelUsageReconciled` | Provider/accounting evidence, old reservation, observed usage | Cho phép bổ sung accounting sau finish; không mở lại loop hoặc sửa canonical response |

Planning chỉ ghi budget estimate; reservation có hiệu lực được lập đúng một lần trong dispatch transaction, không double-reserve từ planning. `ModelRequestPlanned` tạo attempt đầu; `ModelAttemptPlanned` chỉ cho attempts sau. Retry intent, attempt mới và timer được ghi **trước khi chờ**; `TimerElapsed(model_retry)` chỉ resolve time dependency để attempt `Planned` đó được dispatch, không tạo attempt hay retry number mới. Crash lúc chờ giữ nguyên attempt `Planned` và retry đã charge: sau restart host re-arm timer UTC, resume hợp lệ dispatch chính attempt đó, không charge lại. Stop lúc chờ ghi `ModelAttemptCancelled` (pre-dispatch) cùng `TimerCancelled`. Retry budget (số lần) charge lúc lên lịch; reservation token/cost chỉ lập lúc dispatch, nên attempt chưa dispatch không có usage. `ModelResponseRecorded` và các `ToolCallPlanned` từ response được chọn nằm cùng transaction để current step không bị lệch frontier. Tool arguments vẫn cần validate trước thực thi.

## 4. Tool invocation và attempts

| Event | Fields/control facts chính | Guard / thay đổi projection |
| --- | --- | --- |
| `ToolCallPlanned` | Tool call/source position, validated-or-raw input ref, descriptor/effect-class version, first attempt | Response đã complete/selected; tạo candidate, chưa cấp quyền |
| `ToolCheckReset` | Old/new check generation, owner invalidation/read-back receipt, resolved dependency refs | Recovery của Checking/AwaitingApproval/Ready chưa dispatch; invalidate request/receipt/reservation và gỡ dependency cùng batch về Planned; không project refusal hoặc chạy check từ replay |
| `ToolCheckStarted` | Frontier cursor, invocation/attempt, check generation | Chỉ tool tại frontier; chuyển `Checking`, validate input và nối gateway qua adapter |
| `ToolApprovalRequested` | Check generation, owner request/ref/revision, exact args ref, approver route, expiry, gate observation ([interaction §6.2](/dev-kit/core-harness/interaction#62-gate-observation)) | Owner receipt hợp lệ; tạo approval dependency đúng một tool |
| `ToolApprovalResolved` | Check generation, owner resolution/evidence, approved/denied/expired/invalidated | Chỉ receipt đúng request; gỡ dependency và cập nhật approval observation |
| `ToolReadyRecorded` | Check generation, validated args ref, gate observation, one-use approval receipt ref nếu cần | Sau check/approval đủ điều kiện scheduling; không là durable grant |
| `ToolDispatchStarted` | Attempt/fence/check generation, current dispatch authorization/receipt ref, budget reservation | Worker slot đã giữ; append trước handoff; gateway revalidate/claim receipt tại execute, không hỏi đôi |
| `ToolResultRecorded` | Result/disposition ref, code, effect evidence, source position | Terminal result success/failure/denied/refused/cancelled hoặc synthetic disposition abandoned_unknown; project đúng một canonical result |
| `ToolOutcomeUnknown` | Attempt, cause class, possible exposure và evidence refs | Không có completion phù hợp; không tự chọn retry |
| `ToolReconciled` | Operation receipt/proof, observed outcome | Owner/provider xác nhận; thêm evidence vào attempt cũ, không chạy lại tool |
| `ToolAttemptAbandoned` | Class/policy hoặc user disposition ref, next action retry/close | Host chỉ tự abandon theo class contract; exposure unknown vẫn được giữ |
| `ToolAttemptPlanned` | New attempt, previous attempt, same logical operation/input/key refs | Class/policy/window, current scope và budgets cho phép; không blind retry side effects |
| `InvocationQuiesceRequested` | Target attempt, reason, cancellation/suspension command ref | Yêu cầu dừng, chưa là stop proof; áp dụng cả model/tool |

Denied/refused/cancelled trước dispatch được kết thúc bằng `ToolResultRecorded` có outcome tương ứng. Owner denial/expiry có terminal refusal ngoài recovery phải cùng batch với terminal result/disposition; invalidation do restart dùng ToolCheckReset + gỡ dependency, không tạo canonical refused; approved cùng batch với `ToolReadyRecorded` hoặc refusal nếu current checks thất bại. Không để tool chờ một request đã resolved.

`ToolResultRecorded(abandoned_unknown)` là canonical control disposition, không là observation rằng tool kết thúc. Nó chỉ hợp lệ sau `UnknownAccepted(close)` hoặc `ToolAttemptAbandoned(next=close)` hoặc `RunClosureConfirmed` trong cùng batch; `exposure=unknown` vẫn được giữ. Abandon để retry không project canonical result trước attempt được chọn.

Interaction bridge phải có owner operation identity và read-back/ensure contract để không tạo hai câu hỏi nếu crash khi nối request. `ToolApprovalRequested` chỉ ghi receipt thật, không tự fabricate request ID. Check/request/execute và one-use receipt theo [approval protocol](/dev-kit/core-harness/architecture#approval-qua-owning-gateway) là yêu cầu tường minh của G-04/G-05; không suy ra execution transaction bao trùm interaction owner transaction.

Retry/abandon trong bảng áp dụng cho attempt. Logical invocation chỉ đóng khi có selected terminal disposition; abandon để retry chưa đóng invocation, attempt mới cùng invocation được tạo theo policy/timer. Chấp nhận unknown để close thì không còn attempt mới.

## 5. Timer, budget và dependency facts

| Event | Fields/control facts chính | Guard / thay đổi projection |
| --- | --- | --- |
| `TimeBudgetWindowOpened` | Window ID/generation/incarnation, finite tranche reservation, policy, monotonic baseline reference | Admitted và current resume authorization, runnable/active; cùng TimerScheduled(run_deadline); không mở cho Queued/quiescent wait |
| `TimeBudgetWindowClosed` | Window, measured elapsed/checkpoint hoặc unknown tail coverage, reservation disposition | Measured close release unused tranche với evidence; crash invalidate timer generation, giữ unknown reservation tới explicit resume; không charge downtime |
| `TimerScheduled` | ID/generation, purpose/target/window, clock domain, scheduling deadline, chosen backoff/policy | Không đọc clock trong reducer; thêm pending timer; chỉ wait-producing purpose tạo dependency, run_deadline không làm run Waiting |
| `TimerElapsed` | Timer/generation, trusted observed time | Chỉ sau `TimerFired` hợp lệ; resolve đúng timer một lần; run_deadline hợp lệ đóng/charge active window; exhausted mới tạo stop budget cùng batch |
| `TimerCancelled` | Timer/generation, cause reference | Pending timer không được đánh thức execution sau stop/finish |
| `BudgetObserved` | Usage/reservation counters, known/unknown coverage, source attempt/window, measured hoặc reserved_after_crash basis | Không double-count, không đổi unknown thành zero |

Worker capacity dùng RunBlockAdded(worker_capacity, pool/generation/frontier) khi không có slot và RunBlockCleared cùng dispatch khi slot đã giữ; khi quiescent lifecycle Waiting, time window đóng. Vault/pause/dependency observations dùng `RunBlockAdded/Cleared` với kind/reference rõ ràng. Structured question cũng liên kết interaction owner bằng blocker `user_input`; không parse text assistant để tạo wait state.

Timer expiry chỉ là fact thời gian; approval outcome cần owner receipt. `RunFinished` có thể cùng batch cancel các timers còn pending. Timer/accounting projection không có worker tự ghi DB.

## 6. Command surface tối thiểu

Tên là logic, chưa là tool/API mới. Mỗi command có authenticated origin, command ID, expected target revision/fences và protected content refs khi cần.

| Command / observation | Nguồn | Events có thể tạo |
| --- | --- | --- |
| `AcceptRun`, `AdmitRun`, `AcquireRunOwnership` | User ingress / session owner | Run accepted/admitted/ownership facts |
| `AdvanceRun`, `PrepareDispatch` | Coordinator scheduling | Step/model/tool planning, checks hoặc dispatch facts |
| `ObserveModelStream/Response/Failure` | Bound model worker | Model attempt facts và usage; không do model body tự tạo provenance |
| `ObserveToolCheck/Approval/Result` | Bound gateway/interaction/tool adapter | Tool readiness/approval/result facts |
| `RequestStop` | Trusted user, authorized parent hoặc host policy | Stop intent, quiesce, cancellations và eventual finish |
| `ObserveVault/HostPause/Dependency` | Owner-bound observation | Run blockers và quiesce requests nếu cần |
| `TimerFired` | Owned scheduler với typed UTC/monotonic clock input, window/incarnation khi cần; admission hoặc queue revision theo target | `TimerElapsed`, hoặc reject/no-op nếu stale/early |
| `RecoverRun`, `ReconcileInvocation` | Current coordinator + owner evidence | Unknown/interruption/reconciliation/recovery facts |
| `AcceptUnknown` | Trusted user v1, exact payload preview/revision | Unknown accepted/dispositions và explicit close |
| `CloseRunWithoutPayload` | Trusted local user/host v1, metadata-only preview, run revision/exact attempt/cause set; vault không bắt buộc | RunClosureConfirmed, dispositions (unknown giữ exposure, pre-dispatch cancelled), StepAborted nếu có, TimerCancelled/TimeBudgetWindowClosed nếu cần, RunFinished(abandoned hoặc abandoned_unknown); clear đúng admission; context requirement theo unavailability reason |
| `SelectRunContext` | Trusted user/session owner, queued target, mode fresh/continue, expected queue/run/context revisions | ContextBoundarySelected + RunAdmitted cùng transaction khi queue/scope/vault cho phép; continue validate toàn bộ payload/pairs, fresh tăng epoch; clear context requirement khi commit |
| `ResumeRun` | Session owner với explicit user queue/resume decision và current scope; không cấp tool permission | Revalidate vault/dependencies, conservative-charge unknown time tranche bằng BudgetObserved, clear recovery_admission khi hợp lệ; budget hết thì stop budget, chỉ mở time window nếu runnable |
| `ObserveAccounting` | Current owner/provider evidence | Budget/usage reconciliation, kể cả sau finish |

Catalog không tự tạo permission cho caller. Parent session chỉ được gửi các command trong tree/scope contract hiện hữu; không có quyền tự xác nhận mọi unknown hoặc mọi approval.

## 8. Trace B — crash giữa tool dispatch và explicit close

Giả định: T1 là `side_effecting`, cần approval user. Không có time budget trong trace. Worker slot được giữ trước dispatch; đây là một run riêng, sequence bắt đầu từ 1; các hàng có số sequence là transaction batch. Run kết thúc bằng user chấp nhận uncertainty, không khẳng định external effect đã dừng.

| Seq / mốc | Events / command | Facts sau commit |
| --- | --- | --- |
| 1 | `RunAccepted(R2,inputRef)` | `Queued` |
| 2–4 | `RunAdmitted(token=7)`, `StepStarted(S1)`, `ModelRequestPlanned(M1,A1)` | Control admission của R2; model attempt `Planned` |

| 11 | `ToolApprovalRequested(T1,ownerReceipt,argsRef)` | `Waiting(approval)`; chỉ request owner còn sống mới answerable |
| 12–13 | `ToolApprovalResolved(approved)`, `ToolReadyRecorded(T1,argsRef)` | Tool `Ready`; `Running/processing_tools`, receipt một lần do gateway sở hữu; execute revalidate mà không hỏi đôi |
| 14 | `ToolDispatchStarted(T1,TA1,token=7)` | Intent `dispatching`; có thể đã hoặc chưa handoff |
| Crash | Tool có thể đã thay đổi hệ thống ngoài; chưa commit result | Không có completion evidence; không suy ra failed/chưa chạy |
| Restart prerequisite | OS đã trả exclusive data-directory lock của host cũ; host mới lấy lock rồi tạo incarnation | Vault khởi tạo locked; trong trace owner vẫn báo locked tại recovery revision; chưa được dispatch hoặc xem protected args |
| 15–19 | `RunOwnershipAcquired(token=8)`, `RunBlockAdded(vault_locked)`, `RunBlockAdded(recovery_admission)`, `ToolOutcomeUnknown(T1,TA1)`, `RunInterrupted(effect_unknown,T1)` | `Interrupted`; giữ cả vault/recovery wait reasons và exposure; token 7 mất quyền ghi, không chứng minh tool đã dừng |
| Unlock / 20 | Vault owner xác nhận mở; `RunBlockCleared(vault_locked)` | Đọc protected exact args để preview; vẫn Interrupted, recovery_admission chưa được gỡ |
| User command | Trusted UI preview đúng args/target, attempt/revision và uncertainty; `AcceptUnknown(close)` | Cần vault mở; close authorization này không cấp resume hoặc permission chạy lại |
| 21–25 | `UnknownAccepted(T1,TA1,close)`, `ToolResultRecorded(abandoned_unknown)`, `RunRecoveryCleared`, `StepAborted(unknown_close)`, `RunFinished(abandoned_unknown)` | Đóng control admission, invalidate recovery dependency/timers; canonical result nói unknown; exposure và writer/resource guards vẫn ở owner |

Các events ownership, blockers và unknown classification ở seq 15–19 MUST commit **cùng recovery transaction**, để không có committed view coi TA1 sau restart là worker còn sống hoặc có thể schedule. Lifecycle sau batch là `Interrupted` theo precedence.

Nếu có receipt thật, một **nhánh thay thế** sau seq 20 là `ToolReconciled` + `ToolResultRecorded` + `RunRecoveryCleared`; nếu không còn interruption/active effect, run là `Waiting(recovery_admission)`. Nếu đối soát khi vault vẫn khóa, wait reasons còn cả `vault_locked`. Chỉ resume authorization từ queue/scope hiện tại mới cho `RunBlockCleared(recovery_admission)` và tiếp tục S1; unlock không tự resume. Không ghi `UnknownAccepted` trong nhánh đã đối soát xong. Result evidence và process-stop proof vẫn là hai facts khác nhau khi xét quyền dùng tài nguyên tiếp.

Nếu T1 là `pure_read`, host policy có thể dùng `ToolAttemptAbandoned` rồi `ToolAttemptPlanned` sau revalidation, thay vì yêu cầu user xác nhận unknown của thao tác ghi. Attempt cũ và uncertainty vẫn trong history; policy không tự release write/resource ownership. Timer/approval/accounting sau restart không được tự chạy lại effect này.

## 9. Trace C — đóng khi không mở được payload

Bắt đầu từ R2 sau recovery seq 19 của Trace B; owner vẫn báo vault locked, không có known live worker, TA1 exposure unknown. Host không mở protected args. Các seq dưới đây thuộc nhánh thay thế, không tiếp nối nhánh unlock.

| Seq / command | Event batch / observation | Kết quả |
| --- | --- | --- |
| User preview | Trusted host dựng metadata-only preview với R2/revision, T1/TA1 và enum vault_locked (hoặc payload_missing/corrupt khi owner có evidence) | Không giả có args/target preview; user xác nhận đóng bất kể unknown effects |
| CloseRunWithoutPayload | Kiểm tra user/session ownership, exact revision/attempt set và SM-05; metadata-only dedup | Nếu revision đổi hoặc còn known live worker chưa quiesce thì chưa finish, phải dựng preview mới hoặc xử lý worker |
| 20–24 | RunClosureConfirmed(metadata_only), ToolResultRecorded(abandoned_unknown), RunRecoveryCleared(disposition=accepted_unknown), StepAborted(unavailable_close), RunFinished(abandoned_unknown) | Clear R2 admission và dependencies; contextRequirement=revalidation_required nếu chỉ vault_locked, fresh_required nếu payload_missing/corrupt; exposure/resource guards còn nguyên.
