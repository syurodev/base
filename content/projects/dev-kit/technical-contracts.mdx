# Technical contracts

Trang này chốt các contract runtime đang hiện diện trong checkout DevKit tại
`/Users/syuro/Workspace/dev-kit`. Mục tiêu là giúp người implement biết đâu là
biên giới ổn định, đâu là chi tiết nội bộ có thể thay đổi mà không làm vỡ UI.
Để xem trạng thái module hiện tại và phần nào còn thiếu runtime, xem
[Implementation status](/dev-kit/implementation-status). Ma trận control và ADR
tương ứng nằm ở [Security controls](/dev-kit/security-controls) và
[Architecture decisions](/dev-kit/architecture-decisions).

## Boundary map

Phần lớn contract public hiện tại đi theo chuỗi capability-gated built-in:

`frontend/src/bridge/*` → `internal/bridge/AppService.*` →
`AppService.call(...)` → `internal/capabilities/Gateway.Call(...)` →
`internal/services/*` hoặc `internal/commands/Registry.Execute(...)` →
`Repository` / `internal/storage` / endpoint bên ngoài.

Hai ngoại lệ hiện có cần đọc cùng boundary này:

- `AppService.ListModules()` trả registry data trực tiếp từ
  `internal/modules.Registry` và không đi qua `AppService.call(...)` hoặc
  capability audit.
- DB/SSH service không dừng ở repository/storage; sau khi lookup profile,
  `internal/services/database.Service` và `internal/services/ssh.Service` còn
  đi tiếp tới remote database/SSH endpoint.

Boundary này được thể hiện ở:

- `frontend/src/bridge/client.ts`
- `frontend/src/bridge/{notes,database,ssh,vault,commands}.ts`
- `internal/bridge/app_service.go`
- `internal/bridge/gateway.go`
- `internal/capabilities/gateway.go`

Ý nghĩa contract:

- UI gọi typed adapter trong `frontend/src/bridge/*`, không gọi trực tiếp
  generated binding từ feature module.
- Bridge Go là choke point public duy nhất cho built-in module hiện tại.
- Capability Gateway kiểm tra quyền và audit trước khi handler thật chạy.
- Core service chỉ thấy interface như `Repository`, `Vault`, `commands.Registry`;
  service không biết UI hoặc component render.
- `ListModules` là bridge read-only public helper, không phải capability-gated
  operation.

## Internal module manifest contract

Built-in modules đăng ký metadata qua `ModuleManifest`, không đăng ký handler
hoặc permission grant trong manifest. Contract hiện tại gồm:

| Field | Contract |
| --- | --- |
| `id` | Module identifier ổn định, lowercase và namespaced theo identifier rules. |
| `title` | Tên hiển thị public của module. |
| `version` | Semantic version của module, hiện built-in modules dùng `1.0.0`. |
| `apiVersion` | Version của internal extension contract; version hiện tại là `1`. |
| `commands` | Danh sách command contribution IDs. Runtime handler vẫn nằm ở command registry/service boundary. |
| `views` | Danh sách view contribution IDs. Component mapping vẫn do frontend built-in giữ local. |
| `capabilities` | Declaration metadata để mô tả nhu cầu của module; không tự cấp quyền. |

Backend `internal/modules.Registry` validate manifest trước khi mutate state,
reject duplicate module/command/view/capability, và trả list deterministic với
snapshot caller-owned. Built-in descriptors hiện được đăng ký từ
`internal/app/app.go` cho `tools`, `notes`, `database` và `ssh`.

`apiVersion` là compatibility field của contract; type giữ tên
`ModuleManifest`. Khi permission được thực thi, grants vẫn phải được cấp
explicit trong policy/container và sensitive calls vẫn đi qua
`AppService.call(...)` + Capability Gateway.

## Module metadata bridge and frontend parity

`AppService.ListModules()` expose duy nhất public metadata của manifest qua
`ModuleDTO`: version, API version, command/view IDs và capability declarations.
Bridge không expose handler, secret, raw grant hoặc runtime implementation
detail. JSON bridge dùng `api_version`; typed frontend adapter map field này về
`apiVersion`.

Frontend built-in manifests giữ component mapping local và parity-check với
metadata từ backend theo module ID, title, version, API version, commands,
views và capabilities. Mismatch tạo safe metadata warning; backend data không
được dùng để dynamic-load component hoặc execute arbitrary code.

Workbench xử lý loading/error fallback, module không tương thích và empty state
ở mức minimal functional UX. Module unavailable không được render view hoặc
đưa command vào Command Palette; các module tương thích khác vẫn tiếp tục hoạt
động.

Contract này chưa mở external plugin runtime. Dynamic loading, marketplace,
MCP runtime và sync vẫn là các phase riêng, ngoài runtime surface hiện tại.

## Bridge contract

`internal/bridge` hiện publish các family operation sau:

| Family | Public methods | Subject / capability / scope pattern | Evidence |
| --- | --- | --- | --- |
| Vault | `VaultStatus`, `SetupVault`, `UnlockVault`, `UnlockVaultWithRecovery`, `LockVault` | `builtin.vault` / `vault:manage` / `vault` | `internal/bridge/vault.go` |
| Notes | `NotesList`, `NotesSearch`, `NotesCreate`, `NotesGet`, `NotesDelete` | `builtin.notes` / `notes:read` hoặc `notes:write` / `note:list`, `note:search`, `note:new`, `note:<id>` | `internal/bridge/notes.go` |
| Database | `DBListProfiles`, `DBCreateProfile`, `DBDeleteProfile`, `DBTestConnection`, `DBQuery` | `builtin.database` / `db:query` / `profile:list`, `profile:new`, `profile:<id>` | `internal/bridge/database.go` |
| SSH | `SSHListProfiles`, `SSHCreateProfile`, `SSHDeleteProfile`, `SSHObserveHostKey`, `SSHTrustHostKey`, `SSHTestConnection`, `SSHRunCommand` | `builtin.ssh` / `ssh:connect` / `profile:list`, `profile:new`, `profile:<id>` | `internal/bridge/ssh.go` |
| SSH forwarding | `SSHStartForward`, `SSHListForwards`, `SSHStopForward` | `builtin.ssh` / `ssh:forward` / `profile:<id>`, `forward:list`, `forward:<id>` | `internal/bridge/ssh.go`, `internal/services/ssh/forwarding.go` |
| Tools | `ExecuteCommand` | `builtin.tools` / `tools:hash` / `command:<id>` | `internal/bridge/app_service.go`, `internal/commands/registry.go` |
| Search | `VaultSearch` | `builtin.search` / `vault:search` / `item:search` | `internal/bridge/search.go` |
| Modules | `ListModules` | no capability gate; registry read-through only | `internal/bridge/app_service.go`, `internal/modules/registry.go` |

Hai quy tắc bridge quan trọng:

- ID record và command được làm mờ thành scope opaque qua `recordID()` và
  `commandID()` trong `internal/bridge/gateway.go`; ID không hợp lệ bị hạ về
  giá trị `"invalid"` thay vì đưa raw input vào audit/policy path.
- Typed adapter ở frontend map DTO snake_case sang shape UI riêng
  (`frontend/src/bridge/{notes,database,ssh,vault,commands}.ts`), vì vậy UI
  contract ổn định là adapter function, không phải generated binding thô.

## Capability contract

Capability Gateway nhận một `CallRequest` gồm `SubjectID`, `Capability`,
`Scope`, `Metadata`, `Handler` rồi:

1. kiểm tra policy qua `internal/permissions/policy.go`,
2. redact metadata qua `internal/audit/redact.go`,
3. ghi audit event,
4. chỉ gọi handler nếu grant hợp lệ.

Built-in subjects đang được container cấp sẵn trong
`internal/app/container.go`:

- `builtin.tools`
- `builtin.notes`
- `builtin.database`
- `builtin.ssh`
- `builtin.vault`
- `builtin.search`

Capability names public hiện tại:

- `tools:hash`
- `notes:read`
- `notes:write`
- `db:query`
- `ssh:connect`
- `ssh:forward`
- `vault:manage`
- `vault:search`

Scope families hiện tại:

- `command:<command-id>`
- `note:list`
- `note:search`
- `note:new`
- `note:<record-id>`
- `profile:list`
- `profile:new`
- `profile:<record-id>`
- `forward:list`
- `forward:<forward-id>`
- `vault`
- `item:search`

Generic command scope construction is broader than the runtime surface today:

- bridge formats `command:<opaque-id>` for command execution in general;
- the current container registers only one executable command, `tools.hash`;
- the only live grant for that surface is `builtin.tools` / `tools:hash` /
  `command:tools.hash` in `internal/app/container.go`.

Rule matching trong `internal/permissions/policy.go` hỗ trợ ba dạng:

- exact scope, ví dụ `vault`
- prefix-bounded wildcard, ví dụ `note:*` hoặc `profile:*`
- global `*`

Trong container hiện tại, built-in grants dùng exact hoặc prefix scope; đây là
pattern nên giữ cho caller ngoài dự đoán được behavior mà không phụ thuộc vào
chi tiết service nội bộ.

## Error contract

Public error qua bridge hiện được chuẩn hóa về `internal/apperrors.AppError`
với ba field ổn định:

- `code`
- `message`
- `recoverable`

Evidence: `internal/apperrors/errors.go`, `internal/bridge/errors.go`,
`frontend/src/bridge/errors.ts`.

Bridge chỉ publish nhóm code nhỏ sau:

- `validation_failed`
- `vault_locked`
- `permission_denied`
- `connection_failed`
- `operation_cancelled`
- `internal_error`

Behavior công khai:

- `context.Canceled` và `context.DeadlineExceeded` được ưu tiên map thành
  `operation_cancelled`.
- `vault.ErrLocked` được ưu tiên map thành `vault_locked`, kể cả khi bị wrap.
- Database và SSH fallback về `connection_failed` thay vì lộ driver/network
  detail.
- Safe validation message chỉ đi qua allowlist trong
  `safeValidationMessages`; các message khác không được coi là public contract.
- `NewWithDetails(...)` vẫn tồn tại cho source compatibility nhưng chi tiết
  bổ sung không thuộc public contract và không nên phụ thuộc vào nó.

Boundary redaction:

- Capability Gateway và audit sink đều đi qua `audit.RedactMap(...)`.
- Key có dạng như `password`, `passphrase`, `private_key`, `secret`, `token`,
  `recovery`, `encryptionKey` sẽ bị thay bằng `[REDACTED]`.
- Transport/error-envelope redaction không cho raw URL, DSN, SQL text lỗi, raw
  driver error, hay command stderr đi qua như một public error body. Riêng
  `SSHRunCommand` vẫn trả `CombinedOutput` trong `CommandResult.Output` như
  payload command rõ ràng, kể cả khi process exit non-zero.

## Persistence contract

Persistence runtime hiện chia làm hai lớp:

1. Shared item store `internal/services/vaultitem` — một `Repository` (memory +
   SQLite) và một `Store` lo storage/crypto/search cho mọi item type.
2. SQLite KV + migration runner dùng chung trong `internal/storage`.

Boundary ổn định:

- Notes/Database/SSH service chỉ phụ thuộc một local `Store` interface (được
  `*vaultitem.Store` thỏa mãn); không còn repository riêng mỗi module.
- `vaultitem.Record` là shape at-rest chung: `id`, `type`, `metadata` (plaintext
  JSON), `payload` (envelope mã hóa, nil nếu type không có secret), `created_at`,
  `updated_at`, `key_version`, `sync_state`.
- Table hiện tại được chốt trong `internal/storage/sqlite.go`:
  `vault_keyring` và `vault_items` (id TEXT PRIMARY KEY, type TEXT, data TEXT).
  Ba bảng cũ `notes`/`connection_profiles`/`ssh_profiles` đã bị drop (migration
  m6) và thay bằng `vault_items`.
- `storage.Migrate(...)` chạy migration forward-only, idempotent, có version,
  bằng `schema_migrations` trong `internal/storage/{sqlite,migrations}.go`
  (m5 tạo `vault_items`, m6 drop bảng cũ).

Phân ranh dữ liệu nhạy cảm và metadata (mỗi type map field vào `metadata`
plaintext và `payload` mã hóa của `vault_items`):

- Notes (`type = "note"`): `Body` được mã hóa trong payload, `Title` là plaintext
  metadata (`internal/services/notes/notes.go`).
- Database profiles (`type = "db-profile"`): chỉ `Password` mã hóa; `Host`, `Port`,
  `Database`, `Username`, `SSLMode` là metadata không nhạy cảm
  (`internal/services/database/database.go`).
- SSH profiles (`type = "ssh-profile"`): chỉ `Secret` mã hóa; `Host`, `Port`,
  `Username`, `AuthMethod`, `HostKeyFingerprint` là metadata không nhạy cảm
  (`internal/services/ssh/ssh.go`).
- Vault keyring vẫn được lưu như một row riêng qua `internal/vault/sqlkeyringstore.go`.

Storage file boundary:

- SQLite được mở với `journal_mode=DELETE`, `foreign_keys=ON`,
  `busy_timeout=5000` và file permission `0600`
  (`internal/storage/sqlite.go`).
- Contract này nói về application-layer encryption + restricted file mode,
  không đồng nghĩa full-disk encryption.

## Encryption envelope contract

Envelope format public cho dữ liệu mã hóa nằm ở:

- `internal/crypto/envelope.go`
- `internal/crypto/aead.go`

Contract hiện tại:

- Version hợp lệ: chỉ `2`.
- Algorithm hợp lệ ở runtime hiện tại: `xchacha20-poly1305`.
- Envelope field ổn định: `version`, `algorithm`, `key_id`, `nonce`,
  `ciphertext`.

V2-only:

- Không còn public API tạo hoặc giải mã envelope V1.
- `OpenWithAD(...)` chỉ nhận V2 và yêu cầu associated data khớp.
- Envelope V1 bị từ chối với lỗi unsupported version; không có migrate tool.
- V2 ràng buộc AAD theo bộ ba `record_type`, `record_id`, `key_id`.
- Canonical AAD được ghép bằng:
  `record_type + NUL + record_id + NUL + key_id`
  trong `internal/crypto/aead.go`.

Binding hiện đang được service dùng:

- Notes: `record_type = "note"`, `key_id = "note-body"`
- Database profile: `record_type = "db-profile"`, `key_id = "db-password"`
- SSH profile: `record_type = "ssh-profile"`, `key_id = "ssh-secret"`

`record_type` giờ chính là `vault_items.type`, và `record_id` là item id; AAD
được `vaultitem.Store` ghép trong cả seal (`Create`) lẫn open (`OpenPayload`) nên
ràng buộc chống swap không đổi.

New secret writes đều đi qua `vaultitem.Store.Create(...)` (gọi `SealV2` bên
trong) từ:

- `internal/services/notes/notes.go`
- `internal/services/database/database.go`
- `internal/services/ssh/ssh.go`

Điều này có nghĩa:

- Record mới ghi từ runtime hiện tại đi theo V2.
- Record V1 cũ không còn được hỗ trợ đọc vì DevKit là greenfield và chưa có dữ
  liệu V1 production cần bảo toàn.

## Compatibility rules

Những thay đổi sau được xem là backward-compatible với caller hiện tại:

- thêm bridge method mới mà không đổi chữ ký method cũ;
- thêm built-in subject/capability/scope mới mà không đổi grant cũ;
- thêm metadata audit mới nếu vẫn redact theo rule hiện tại;
- thêm migration forward-only mới với version mới;
- tiếp tục ghi V2 và giữ `OpenWithAD(...)` bắt buộc AAD matching.

Những thay đổi sau cần migration hoặc quyết định kiến trúc rõ ràng trước khi
coi là hợp lệ:

- đổi tên subject, capability, scope family, hoặc opaque ID rule;
- thay shape public error vượt quá `code/message/recoverable`;
- làm safe validation message phụ thuộc vào raw error nội bộ;
- đổi table name, blob shape, hoặc semantics của `schema_migrations`;
- chuyển plaintext metadata hiện tại (ví dụ note title, DB/SSH profile
  metadata) sang encrypted-at-rest mà không có kế hoạch reindex/migration;
- thêm algorithm mới rồi dùng nó làm default mà không có rule compatibility cho
  reader cũ;
- cho UI hoặc module gọi thẳng service/repository mà bỏ qua `AppService.call`
  và Capability Gateway.
