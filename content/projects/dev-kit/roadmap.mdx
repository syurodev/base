# Roadmap

Roadmap này tách rõ phần đã có runtime trong checkout hiện tại khỏi các phase mới
chỉ dừng ở mức design. Trạng thái dùng đúng vocabulary của
`/dev-kit/implementation-status`; claim implementation luôn đi kèm source hoặc
trang kiểm chứng.

## Phase 0 — Architecture foundation

- Status: Implemented
- Goal: Giữ biên giới local-first đã chạy được: vault, service layer, command/module registry, và Capability Gateway làm choke point cho call nhạy cảm.
- Evidence: `/dev-kit/implementation-status`, `/dev-kit/core-foundation`, `internal/bridge/app_service.go`, `internal/commands/registry.go`, `internal/bridge/gateway.go`, `internal/capabilities/gateway.go`, `internal/modules/registry.go`.
- Done when: Mọi call nhạy cảm đi qua `AppService.call` + Capability Gateway, module built-in đăng ký qua registry, và baseline audit/permission tiếp tục là invariant bắt buộc.
- Dependencies: Quyết định kiến trúc trong `docs/architecture/core-foundation.md` và `docs/architecture/devkit-architecture.md`.
- Out of scope: MCP runtime, sync runtime, external plugin runtime, marketplace.

## Phase 1 — Local MVP

- Status: Implemented
- Goal: Hoàn tất bộ local workflow để DevKit hữu ích hằng ngày mà chưa cần sync hay plugin bên thứ ba.
- Evidence: `/dev-kit/implementation-status` xác nhận Vault, Notes, Tools, Database và SSH đã Implemented; `internal/vault/service.go`, `internal/services/notes/notes.go`, `internal/services/database/database.go`, `internal/services/ssh/ssh.go`, `internal/services/ssh/forwarding.go`.
- Done when: Các module local-first cốt lõi cần cho solo use đều đạt ít nhất `Implemented` trên `/dev-kit/implementation-status`. Vault-item repository đã **Implemented** (unified `vault_items` store + cross-type `VaultSearch`, xem [ADR-008](/dev-kit/architecture-decisions#adr-008-unified-vault_items-store-for-built-in-item-types)); SSH có local và remote TCP forwarding với bind loopback-only, cleanup theo lifecycle, capability riêng và UI quản lý start/stop.
- Dependencies: Phase 0 giữ ổn định storage, crypto envelope, permission boundary, và UI shell local-first.
- Out of scope: SaaS sync, external plugin loading, marketplace, realtime collaboration.

## Phase 2 — Internal Extension API

- Status: Implemented
- Goal: Chuẩn hoá built-in modules quanh `ModuleManifest` và contribution contract ổn định, trong khi vẫn giữ capability gateway là security boundary và chưa chạy code bên ngoài.
- Evidence: Backend manifest và registry ở `internal/modules/registry.go`; built-in descriptors ở `internal/app/app.go`; public metadata ở `internal/bridge/{dto.go,app_service.go}`; frontend manifests, validation và parity-check ở `frontend/src/modules/{registry.ts,*/manifest.ts}` và `frontend/src/workbench/Workbench.tsx`.
- Current implementation: `ModuleManifest` dùng các fields `id`, `title`, `version`, `apiVersion`, `commands`, `views`, `capabilities`. Backend validate manifest, bảo vệ duplicate module/contribution, trả list deterministic và snapshot độc lập; `ListModules` chỉ expose public metadata; frontend built-in manifests đối chiếu parity với backend và có minimal functional UX cho loading/error, unavailable module và empty state. `capabilities` chỉ là declaration metadata, còn grants vẫn do policy/capability gateway quản lý.
- Done when: Combined checkout verification pass; built-in modules dùng contract ổn định, registry/bridge/frontend parity được kiểm chứng, và contribution path vẫn không bypass `AppService.call` + Capability Gateway.
- Dependencies: Phase 0 Capability Gateway + registry; quyết định “internal modules now, untrusted plugins later” trong `docs/architecture/devkit-architecture.md`.
- Out of scope: External plugin runtime, dynamic loading, marketplace, MCP runtime, sync runtime, signing và sandbox runtime.

## Phase 3 — SaaS sync

- Status: Partial
- Goal: Xây local sync foundation zero-knowledge cho multi-device personal use mà chưa thêm SaaS backend production.
- Evidence: `internal/sync/{contract,outbox,envelope,queue,transport,runner,session,httptransport}.go`; orchestration ở `internal/services/syncclient`; persistent state/apply ở `internal/storage/{syncoutbox,syncidentity,syncremote}.go`; bridge/UI ở `internal/bridge/sync.go` và `frontend/src/modules/sync`.
- Current implementation: Phase 3B có authenticated transport/pull/apply/UI. Phase 3C tự capture local create/update/delete qua atomic mutation journal, materialize thành encrypted authenticated outbox khi `SyncNow`, cấp entity version đơn điệu và reconcile ACK theo current head. Local dirty/tombstone chưa ACK không bị remote overwrite/resurrect.
- Done when: Có sync client/queue/conflict flow đầy đủ, blob mã hóa end-to-end, device/session binding, pull/apply policy, bridge/UI tối thiểu, và security review chứng minh server không cần plaintext.
- Dependencies: Local data model ổn định từ Phase 1, envelope/versioning rules từ Phase 0, và contract boundaries từ Phase 2.
- Out of scope: SaaS backend production, team vault, realtime collaboration, server-side plaintext search.

## Phase 4–5 — Plugins and marketplace

- Status: Design only
- Goal: Mở rộng từ internal modules sang external plugins có isolation, rồi mới tới phân phối qua marketplace có kiểm soát.
- Evidence: `/dev-kit/plugins`, `/dev-kit/implementation-status`, `docs/architecture/devkit-architecture.md`, `docs/architecture/core-foundation.md`; checkout hiện chưa có `internal/plugins` hoặc `internal/marketplace`.
- Done when: Phase 4 có plugin runtime với lifecycle/permission/isolation rõ; Phase 5 chỉ mở khi manifest validation, signing, integrity checks, rollback, audit, và sandbox strategy đều đã thành security gate bắt buộc.
- Dependencies: Phase 2 manifest/versioning contract, Capability Gateway policy mở rộng, và security gates trong `/dev-kit/security`.
- Out of scope: Remote third-party loading trước khi có isolation; marketplace như một hạng mục “MVP”.
